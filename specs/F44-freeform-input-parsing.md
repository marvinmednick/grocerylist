## Feature: Free-form Input Parsing

### Context

Parses free-form text typed into the SmartAddItem input field to extract structured fields: item name, count, package type, size, and store hint. Extracted values pre-populate dropdown result rows (qty pills pre-selected, store pills shown when `@hint` is present) so users can type naturally rather than navigating multiple fields manually.

Design decisions recorded in `docs/design/F44-freeform-input-parsing.md`.
Cross-cutting architecture in `docs/design/vocabulary-and-quantity-architecture.md`.

This is the foundation of the input & vocabulary feature chain: **F44 → F79 → F77/F83 → F78/F76**.

### TypeScript Interfaces

These are the core data structures. Define them in `client/lib/parser.ts`.

```typescript
// -- Vocabulary types (in vocabulary.ts) --

interface VocabEntry {
  canonical: string;    // normalized form: "oz", "can", "large"
  aliases: string[];    // all recognized forms including plural: ["ounce", "ounces"]
}

interface Vocabulary {
  units: VocabEntry[];
  packages: VocabEntry[];
  sizeDescriptors: VocabEntry[];
}

// -- Parser types (in parser.ts) --

type TokenType =
  | 'COUNT_SIGIL'       // 2x, 3x
  | 'STORE_HINT'        // @safeway
  | 'NUMBER'            // 2, 1.5, 32
  | 'COMPOUND'          // 8oz, 1.5lb (number fused with unit)
  | 'UNIT'              // oz, lb, gal (standalone)
  | 'PACKAGE'           // cans, bottles, bunch
  | 'SIZE_DESCRIPTIVE'  // large, jumbo, small
  | 'NAME'              // everything else
  // Grouped types (produced by Pass 3):
  | 'QUANTITATIVE_SIZE' // merged NUMBER+UNIT or COMPOUND
  | 'SIZED_PACKAGE'     // merged QUANTITATIVE_SIZE+PACKAGE
  | 'COUNT';            // NUMBER or COUNT_SIGIL when preceding a package

interface ClassifiedToken {
  type: TokenType;
  raw: string;          // original text
  value?: any;          // parsed value (number for NUMBER, stripped hint for STORE_HINT, etc.)
}

interface CandidateFields {
  count: number | null;
  packageType: string | null;     // canonical form
  sizeQty: number | null;
  sizeUnit: string | null;        // canonical form
  sizeDescriptive: string | null; // canonical form
  storeHint: string | null;       // @ stripped
  nameWords: string[];            // remaining NAME tokens, original order
  sizeDescriptiveTokens: string[]; // SIZE_DESCRIPTIVE tokens available for dual-candidacy in Pass 5
}

interface ParsedInput {
  name: string;                    // matched master item name (or candidate if no match)
  matchedItemId: string | null;    // master item ID if matched, null otherwise
  count: number | null;
  packageType: string | null;
  sizeDescriptive: string | null;
  sizeQty: number | null;
  sizeUnit: string | null;
  storeHint: string | null;
  orphans: string[];               // unmatched NAME tokens
}

interface ParseResult {
  interpretations: ParsedInput[];  // ranked: longest name match first
  rawInput: string;                // original input text for one-off add
}

// Lightweight master item reference for Pass 5
interface MasterItemRef {
  id: string;
  name: string;
  default_qty: string | null;
  alternate_qtys: string[] | null;
}
```

### Parser Architecture — Pass-by-Pass Implementation Notes

Follow the design doc (`docs/design/F44-freeform-input-parsing.md`) for the full specification. Key implementation notes per pass:

#### Pass 1 — Tokenize
Split on whitespace. Quoted strings (`"..."` or `'...'`) become single NAME tokens with quotes stripped. Use a simple state machine or regex to handle quoted regions.

#### Pass 2 — Per-Token Classification
Process each token left-to-right. Classification priority (first match wins):
1. Quoted token (from Pass 1) → `NAME` (bypass all classification)
2. `^\d+x$` → `COUNT_SIGIL` (case-insensitive on x)
3. `^@\w+$` → `STORE_HINT` (strip @, store the hint)
4. `^\d+(\.\d+)?$` → `NUMBER`
5. Number fused with recognized unit (`^\d+(\.\d+)?[unit]$`) → `COMPOUND`
6. Recognized unit (exact match against vocabulary) → `UNIT`
7. `\d+-pack` pattern → `PACKAGE` (literal string)
8. Recognized package (exact match against vocabulary) → `PACKAGE`
9. Recognized size descriptor (exact match against vocabulary) → `SIZE_DESCRIPTIVE`
10. Everything else → `NAME`

All vocabulary lookups are case-insensitive. Match against canonical AND all aliases.

#### Pass 3 — Adjacent Token Grouping
Four sub-passes in a loop until stable (max 10 iterations, warn at >4):

- **3a**: `COMPOUND` → `QUANTITATIVE_SIZE`; `NUMBER + UNIT` → `QUANTITATIVE_SIZE`
- **3b**: `QUANTITATIVE_SIZE + PACKAGE` → `SIZED_PACKAGE`
- **3c**: `NUMBER + SIZED_PACKAGE` → reclassify NUMBER as `COUNT`; `NUMBER + PACKAGE` → reclassify NUMBER as `COUNT`; `COUNT_SIGIL + SIZED_PACKAGE` → reclassify as `COUNT`; `COUNT_SIGIL + PACKAGE` → reclassify as `COUNT`
- **3d**: `\d+-pack` literal → `PACKAGE` (already handled in Pass 2; this sub-pass is a safety net)

Emit `console.warn()` with input string if iterations > 4.

#### Pass 4 — Candidate Assembly
Walk the token stream and extract fields by type. A bare `NUMBER` with no adjacent `PACKAGE` or `SIZED_PACKAGE` is treated as count. `NAME` tokens are collected in order. `SIZE_DESCRIPTIVE` tokens are recorded both as potential `sizeDescriptive` metadata AND as dual-candidacy tokens for Pass 5.

#### Pass 5 — Name Resolution
Generate all candidate name strings from `nameWords` combined with `sizeDescriptiveTokens` (power set of dual-candidacy tokens). For each candidate name string, do **bag-of-words matching** against `masterItems`:
- Tokenize both candidate and master item name on whitespace
- Case-insensitive comparison
- Match when token sets are equal (same words, any order)
- No fuzzy matching, no partial/subset matching, no plural normalization (all F77 scope)

All matching candidates produce a `ParsedInput` entry. Rank by longest name match (most tokens consumed). Tokens not consumed by the name match are assigned to their metadata role if applicable, otherwise become orphans.

If no master items match any candidate, `interpretations` is empty — the one-off add path uses `rawInput`.

#### Pass 6 — Output
Wrap the ranked interpretations into a `ParseResult` with `rawInput`.

### Interim Quantity Format (quantityFormat.ts)

Rendering rules for `formatQuantity()`:

| Fields | Output |
|--------|--------|
| `{count: 2}` | `2` |
| `{sizeQty: 1.5, sizeUnit: "lb"}` | `1.5lb` |
| `{sizeDescriptive: "large"}` | `large` |
| `{count: 2, packageType: "loaf"}` | `2 loaves` |
| `{count: 1, packageType: "can"}` | `1 can` |
| `{sizeQty: 32, sizeUnit: "oz", packageType: "box"}` | `32oz box` |
| `{count: 2, sizeQty: 8, sizeUnit: "oz", packageType: "can"}` | `2 8oz cans` |
| `{count: 3, packageType: "12-pack"}` | `3 12-packs` |

Rules:
- Count omitted when null or 1 (implied), EXCEPT when packageType is present (`1 can`)
- Package pluralized when count > 1 using `getPlural()` from vocabulary
- sizeQty + sizeUnit fused with no space (`8oz`, `1.5lb`)
- Order: count, sizeQty+sizeUnit, packageType, sizeDescriptive

`quantityEquals()`: parse both strings through passes 1-4, compare the resulting `QuantityFields` (count, packageType, sizeQty, sizeUnit, sizeDescriptive). `null == null`, numbers compared with tolerance of 0.001.

`isPartialMatch()`: `dbString.toLowerCase().startsWith(userInput.toLowerCase())`.

### SmartAddItem Integration

#### New data flow

```
1. User types in input
2. vocabulary = DEFAULT_VOCABULARY (imported constant)
   masterItems = useMasterItemNames() (React Query, cached)
   stores = useMetadata().stores (existing)
3. parseResult = parseInput(query, vocabulary, masterItems)
4. Render dropdown from parseResult.interpretations
5. One-off row uses parseResult.rawInput
```

The parser runs synchronously on every input change. No debounce needed — passes 1-4 are pure string/lookup operations, and Pass 5 does in-memory array matching against the cached master items list. This is fast for typical household item counts (<1000).

**Fallback behavior:** When `query.length < 2` or when the parser produces no interpretations AND no name_words could be extracted, fall back to showing nothing (same as today's empty search). The one-off add row is always visible when `query.length >= 1`.

#### Dropdown rendering changes

**Result rows** — each `ParsedInput` interpretation becomes a dropdown row:

```
┌─────────────────────────────────────────────────────────┐
│ Chicken Broth  ~~green~~                          [▸]   │
│ Qty: [2 8oz cans ✓] [1] [32oz] [Other] [...]           │
│ Store: [Costco ✓] [Country Market]                      │
└─────────────────────────────────────────────────────────┘
```

- **Item name**: `interpretation.name`. If `matchedItemId` is non-null, render as tappable (adds the matched master item). If null, it's a candidate that didn't match — still show it but styled differently (muted).
- **Orphans**: `interpretation.orphans` rendered struck-through after the item name, in gray/muted color.
- **Qty pills**: see Qty Pill Rendering below.
- **Store pills**: see Store Pill Rendering below. Only shown when `interpretation.storeHint` is non-null.
- **Chevron** (`▸`): opens edit modal with parsed context carried through.

**One-off row** — always at bottom when query is non-empty:
```
Add "2 8oz cans chicken broth @costco" (One-time)  [1] [Other]
```
Uses `parseResult.rawInput`. Qty chips: `1` default + Other (same as today's one-off).

#### Qty pill rendering

For each result row with a matched master item:

1. Get the matched item's `default_qty` and `alternate_qtys` from the cached `masterItems` list
2. Get the parsed quantity: `formatQuantity({ count, packageType, sizeQty, sizeUnit, sizeDescriptive })` from the interpretation
3. Check if parsed qty exactly matches (via `quantityEquals`) any default/alternate → if yes, pre-select that pill (dedup — don't show parsed value as separate pill)
4. If parsed qty doesn't match any existing pill, inject it as the first pill (selected)
5. Sort remaining pills: partial matches (via `isPartialMatch` with the raw qty text user typed) first, then non-matching
6. Append "Other" button
7. Apply 2-row cap. If pills overflow, show `...` as last visible pill (tapping opens edit modal)

**"Other" behavior change** (replaces F15's floating popover):
- Tapping "Other" replaces the entire pill row with a `TextInput` pre-filled with the parsed qty value (or empty if none parsed) + an `✕` button
- `✕` returns to pill view
- TextInput auto-focuses
- Keyboard Return submits the value

#### Store pill rendering

Only rendered when `interpretation.storeHint` is non-null:

1. Prefix-match `storeHint` against all stores from `useMetadata()` (case-insensitive `store.name.toLowerCase().startsWith(hint.toLowerCase())`)
2. If 0 matches: show hint text as unresolved (muted, no pills)
3. If 1 match: single pill, pre-selected
4. If 2+ matches: show as pills, first match pre-selected. One-line cap; `...` overflow opens edit modal
5. Pills update live as user refines the hint in the input

Pre-selected means the matched store will be used when the user taps to add. User can tap a different store pill to override.

#### Edit modal enhancements

When opened from a parser-driven row:

- **Qty text input**: pre-filled with the parsed quantity string. "Usual Quantities" tags below sorted with partial matches first.
- **Store list**: if `storeHint` is present, show matching stores first. A `▸ More` row expands to show remaining stores. Matching stores stay at top after expansion. If no hint, behaves as today.

### Acceptance Criteria

**Parser core:**
- [ ] Typing `2 milk` pre-selects qty=2 pill and searches for "Milk"
- [ ] Typing `milk @safeway` shows a Safeway store pill (pre-selected) and searches for "Milk"
- [ ] Typing `2x 8oz cans chicken broth @safeway` pre-selects qty="2 8oz cans", shows Safeway store pill, and searches for "Chicken Broth"
- [ ] Typing `1.5 lb chicken` pre-selects qty="1.5lb" and searches for "Chicken"
- [ ] Typing `large avocado` when both "Large Avocado" and "Avocado" exist shows two interpretations ranked: "Large Avocado" first, "Avocado" with size=large second
- [ ] Typing `large green avocado` when "Large Avocado" exists shows "Large Avocado" with "green" struck-through
- [ ] Typing `'5 hour energy'` treats the quoted text as a single name token (no count extraction)
- [ ] `@co` matching both "Costco" and "Country Market" shows both as store pills

**Qty pills:**
- [ ] Parsed qty that exactly matches an alternate_qty pre-selects that pill (no duplicate pill)
- [ ] Parsed qty that doesn't match any alternate is shown as an extra pill (first position, selected)
- [ ] Alternates are sorted with partial matches to parsed input first
- [ ] When pills exceed 2-row cap, `...` button appears and opens edit modal
- [ ] Tapping "Other" replaces pill row with text input pre-filled with parsed qty + `✕` dismiss

**Store pills:**
- [ ] No store pills shown when input has no `@hint`
- [ ] Store pills update live as user refines the `@hint`
- [ ] User can tap a different store pill to override pre-selection

**Edit modal:**
- [ ] Qty text input is pre-filled with parsed quantity value
- [ ] Store list filtered by `@hint` matches, with `▸ More` to expand
- [ ] After expanding, matching stores remain at top

**One-off add:**
- [ ] One-off add row uses the full raw input text
- [ ] When no master item matches exist, one-off add is still available

**Robustness:**
- [ ] Inputs with no recognizable structure are treated as pure name search (graceful degradation)
- [ ] Empty input shows nothing (same as today)
- [ ] Parser handles mixed case, extra whitespace gracefully
