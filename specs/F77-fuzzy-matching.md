## Feature: Fuzzy Matching in Smart Add

### Context

Enhances the SmartAddItem input pipeline with typo tolerance, plural normalization, and edit-distance matching at the token level. Rather than adding a separate "fuzzy results" section to the dropdown, fuzzy matching is integrated into the existing name resolution, vocabulary classification, and alias expansion steps — making the current ranked list smarter without changing the dropdown UI.

Design decisions recorded in `docs/design/F77-fuzzy-matching.md`.

Addresses USER_SCENARIOS.md Scenario 1 (quick add) and DESIGN.md §4E (fuzzy matching & filtering) by reducing the impact of typos on mobile keyboards.

**`client/lib/parser.ts`**
- Import `levenshteinDistance`, `editDistanceThreshold`, `normalizePlural` from `fuzzyMatch.ts`
- Import `fuzzyLookupUnit`, `fuzzyLookupPackageEntry`, `fuzzyLookupSizeDescriptor` from `vocabulary.ts`
- **`classifyTokens`**: After all exact lookups fail and before returning `NAME`, try fuzzy vocab lookups in order: unit → package → size descriptor. First fuzzy match wins. This means a typo'd vocab word gets classified correctly instead of falling through to NAME.
- **`consumeTokens`**: Replace with `consumeTokensFuzzy` (or extend) — when exact match fails for a token against the target list, try: (1) plural-normalized exact match, (2) edit-distance match within threshold. - **`resolveNames`**: Update to use the new `consumeTokensFuzzy`. The `fuzzyCount` from the consume result is attached to each `ParsedInput` (see interface changes below). Dedup and sort updated to use the new scoring model.
- **`expandAliases`**: When exact alias key lookup fails (`wordAliases.get(word)` returns undefined), scan all alias keys with edit distance. Accept the closest key within threshold. The alias map is small (20–100 entries), so linear scan is acceptable.
- **`isPreferredInterpretation`**: Update to use the new scoring model (see Ranking section below).
- **`parseInputInternal`**: Update final sort to use match quality score instead of just name token count.
- **`ParsedInput` interface**: Add `fuzzyCount: number` field — the number of name tokens that required fuzzy or plural-normalized matching (0 for all-exact matches).

**`client/components/SmartAddItem.tsx`**
- **`prefixFallbackInterpretations`**: Extend the word-matching logic. Currently checks `word.startsWith(token)` for each token. Add two additional tiers when prefix match fails: (1) plural-normalized prefix match — `normalizePlural(word).startsWith(normalizePlural(token))`, (2) edit-distance match within threshold. Track fuzzy count per result and set `fuzzyCount` on the `ParsedInput`.
- **`rankedInterpretations`**: Update the merge/ranking logic to use the match quality score. Currently: exact parser (no orphans) → fallback → parser (with orphans). Replace with: sort all merged results by match quality score (descending), then by name token count (descending) for ties.

### New Files

**`client/lib/fuzzyMatch.ts`** — Pure utility functions for fuzzy matching. No React hooks, no side effects.

```typescript
/**
 * Compute Levenshtein edit distance between two strings.
 * Both inputs are lowercased before comparison.
 */
export function levenshteinDistance(a: string, b: string): number;

/**
 * Return the maximum allowed edit distance for a word of the given length.
 * - length < 3: 0 (no fuzzy matching)
 * - length 3-4: 1
 * - length >= 5: 2
 */
export function editDistanceThreshold(wordLength: number): number;

/**
 * Check if two words are a fuzzy match (within edit distance threshold).
 * Threshold is based on the shorter word's length.
 * Both words must be >= 3 chars for fuzzy matching to apply.
 */
export function isFuzzyMatch(a: string, b: string): boolean;

/**
 * Find the best fuzzy match for `query` among `candidates`.
 * Returns the candidate with the smallest edit distance within threshold,
 * or null if no candidate is close enough.
 * On ties, returns the shorter candidate (prefer simpler forms).
 */
export function bestFuzzyMatch(query: string, candidates: string[]): string | null;

/**
 * Normalize common English plural suffixes to singular form.
 * Rules applied in order:
 * 1. -ies → -y (berries → berry, cherries → cherry)
 * 2. -ves → -f (loaves → loaf) — only for known grocery patterns
 * 3. -es → remove (tomatoes → tomato, potatoes → potato, bunches → bunch)
 * 4. -s → remove (breasts → breast, apples → apple)
 *
 * Does NOT normalize if the result would be < 3 chars.
 * Does NOT normalize words that are already recognized vocabulary
 * (handled separately by vocab lookups).
 */
export function normalizePlural(word: string): string;
```

## Ranking

### Match Quality Score

Each input name token is scored by how it matched against an item:

| Match type | Score | Examples |
|-----------|-------|---------|
| Exact match | 2 | "chicken" → "chicken" |
| Plural-normalized exact | 2 | "breasts" → "breast" (after normalization) |
| Prefix match (existing) | 2 | "chick" → "chicken" (prefix fallback) |
| Fuzzy match (edit distance) | 1 | "rest" → "breast", "chiken" → "chicken" |
| Orphan (unmatched) | 0 | — |

**Item rank** = sum of token scores. Higher is better.

**Tiebreakers** (in order):
1. Fewer fuzzy matches (more exact = more confident)
2. Longer item name in tokens (more specific match)
3. `matchedVia === 'name'` preferred over `'alias'` (existing rule)

### Updated `isPreferredInterpretation`

Replace the current logic:
```typescript
// Current: compare orphan count, then matchedVia
function isPreferredInterpretation(next: ParsedInput, current: ParsedInput): boolean
```

With a score-based comparison:
```typescript
function matchQualityScore(interpretation: ParsedInput): number {
  const nameTokenCount = splitName(interpretation.name).length;
  const exactCount = nameTokenCount - interpretation.orphans.length - interpretation.fuzzyCount;
  return exactCount * 2 + interpretation.fuzzyCount * 1;
  // orphans contribute 0
}

function isPreferredInterpretation(next: ParsedInput, current: ParsedInput): boolean {
  const scoreNext = matchQualityScore(next);
  const scoreCurrent = matchQualityScore(current);
  if (scoreNext !== scoreCurrent) return scoreNext > scoreCurrent;
  if (next.fuzzyCount !== current.fuzzyCount) return next.fuzzyCount < current.fuzzyCount;
  if (next.matchedVia !== current.matchedVia) return next.matchedVia === 'name';
  return false;
}
```

### Updated final sort in `parseInputInternal`

Replace the current sort (by name token count descending) with:
```typescript
interpretations.sort((a, b) => {
  const scoreA = matchQualityScore(a);
  const scoreB = matchQualityScore(b);
  if (scoreB !== scoreA) return scoreB - scoreA;
  const tokensA = splitName(a.name).length;
  const tokensB = splitName(b.name).length;
  return tokensB - tokensA;
});
```

### Updated SmartAddItem merge ranking

Replace the current 3-tier concat:
```typescript
// Current
const rankedInterpretations = [
  ...parseResult.interpretations.filter((i) => i.orphans.length === 0),
  ...fallbackResults,
  ...parseResult.interpretations.filter((i) => i.orphans.length > 0),
];
```

With a unified score-based sort:
```typescript
const allResults = [...parseResult.interpretations, ...fallbackResults];
// Dedup by matchedItemId — keep the one with higher score
const bestByItemId = new Map<string, ParsedInput>();
allResults.forEach((r) => {
  if (!r.matchedItemId) return;
  const existing = bestByItemId.get(r.matchedItemId);
  if (!existing || matchQualityScore(r) > matchQualityScore(existing)) {
    bestByItemId.set(r.matchedItemId, r);
  }
});
const rankedInterpretations = [...bestByItemId.values()].sort((a, b) => {
  const scoreA = matchQualityScore(a);
  const scoreB = matchQualityScore(b);
  if (scoreB !== scoreA) return scoreB - scoreA;
  const tokensA = splitName(a.name).length;
  const tokensB = splitName(b.name).length;
  return tokensB - tokensA;
});
```

Note: `matchQualityScore` must be exported from `parser.ts` (or `fuzzyMatch.ts`) so SmartAddItem can import it.

## Acceptance Criteria

- Typing "chicken rest boneless" ranks "Chicken Breast Boneless Skinless" above "Chicken Thighs" (fuzzy "rest"→"breast")
- Typing "2 botles olive oil" produces count=2, package=bottle, name matches "Olive Oil" (fuzzy vocab lookup)
- Typing "chicken breasts" matches "Chicken Breast" (plural normalization)
- Typing "cherries" matches "Cherry" (ies→y normalization, beyond edit distance threshold)
- Typing "chiken" matches "Chicken" (edit distance 1)
- Typing "be" produces NO fuzzy results (< 3 chars, prefix-only as today)
- Typing "chk" with alias "chkn"→"chicken" and no exact alias for "chk" produces chicken items (fuzzy alias key match)
- Exact matches still rank above fuzzy matches for the same item
- Existing parser tests continue to pass unchanged
- No new React hooks, no new API calls, no UI changes
