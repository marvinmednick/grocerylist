## Feature: Store Preferences UI Redesign

### Context

The item edit modal currently renders every store as a row with segmented status buttons. The new UI replaces this with a single compact section: a store dropdown, status pills (tap to set, `—` to clear), an inline comment field for the selected store, a read-only summary of non-neutral preferences, and a read-only list of all store comments at the bottom.

```typescript
const buildStorePreferencesPayload = () => {
  return Object.entries(storePreferences)

    .map(([store_id, pref]) => ({
      store_id,
      status: pref.status as PreferenceStatus,
      comment: pref.comment || null,
    }));
};
```

### UI Spec — Store Preferences Section

Replace the current `<View style={styles.storePreferenceContainer}>` block (and the entire comment sub-section that followed) with:

```
STORE PREFERENCES
──────────────────────────────────────────────
[ ● Costco                              ▾ ]   ← store dropdown
[ — ] [ Pref. ] [ Avoid ] [ Unavailable ]    ← status pills; tap sets; — clears

COMMENT                                       ← shown only when a store is selected
[ comment text...                      ]      ← no Save Comment button; saved with modal Save

Preferred: Costco, Lunardis                   ← read-only summary (non-neutral only)
Avoid: Trader Joe's
Unavailable: Safeway

All Store Comments:                           ← read-only list (any status with comment)
  Costco — "Buy the big pack"
  Trader Joe's — "Organic only"
```

**Store dropdown row:** `TouchableOpacity` — color dot + store name + ChevronDown. Shows "Select store..." in muted gray when nothing selected. Tapping toggles `prefDropdownOpen`. Dropdown list: mapped `View` of all stores (color dot + name); tap selects store, closes dropdown.

**Status pills:** 4 `TouchableOpacity` pills — `—` / `Pref.` / `Avoid` / `Unavailable`. Active: `backgroundColor: '#2563eb'`, white text. Inactive: `backgroundColor: '#f3f4f6'`, `#374151` text. Reads `storePreferences[selectedPrefStoreId]?.status ?? 'neutral'`. On press: if `selectedPrefStoreId` is empty, no-op; otherwise call `updateStoreStatus(selectedPrefStoreId, option.value)` immediately.

**Inline comment field** (visible only when `selectedPrefStoreId` is non-empty):
- Section label: `COMMENT` (same `label` style as other section headers)
- `TextInput`: multiline, value = `storePreferences[selectedPrefStoreId]?.comment ?? ''`, `onChangeText={(text) => updateStoreComment(selectedPrefStoreId, text)}`, placeholder `"Add a note about this store..."`, `placeholderTextColor="#9ca3af"`
- **No Save Comment button** — the comment is written to `storePreferences` state on every keystroke via `onChangeText`. It is persisted when the user taps the modal Save button along with all other changes.
- **Keyboard scroll:** add a `ref` to the modal `ScrollView`. On comment `TextInput` `onFocus`, call `setTimeout(() => scrollViewRef.current?.scrollToEnd({ animated: true }), 100)` so the field is visible above the keyboard.

**Summary display:** Computed from `storePreferences`. For each status in `['preferred', 'avoided', 'unavailable']`, collect store names where `storePreferences[id].status === status`, sort alphabetically, render `"Preferred: Costco, Lunardis"` etc. Only show groups with at least one store. Tapping a store name calls `setSelectedPrefStoreId(storeId)` only (comment field reads directly from `storePreferences`).

**Summary label for each group:** Use the corresponding `STATUS_OPTIONS` label: `Pref.:` / `Avoid:` / `Unavailable:`.

**All Store Comments list** (read-only, below summary): Filter `metadata?.stores` to stores where `storePreferences[store.id]?.comment?.trim().length > 0`. For each: tappable row showing `store.name — "comment text"`. Empty state: `"No comments yet."` in muted gray. Each row: tap → `setSelectedPrefStoreId(store.id)` (comment field reads from `storePreferences` automatically).

**No comment edit modal.** The comment modal from the previous implementation must be removed entirely.

### Acceptance Criteria

- [ ] Store Preferences section shows a store dropdown and 4 status pills (—, Pref., Avoid, Unavailable)
- [ ] Tapping a status pill immediately sets that store's preference (no separate save button needed)
- [ ] Tapping `—` clears the preference for the selected store (sets to neutral)
- [ ] No `+` or `−` buttons present
- [ ] Comment field appears below the pills only when a store is selected
- [ ] Comment field shows the selected store's existing comment (empty if none); updates `storePreferences` on every keystroke
- [ ] No Save Comment button — comment saves with the modal Save button
- [ ] Typing in the comment field does not require a separate commit step before saving the modal
- [ ] Summary shows only non-neutral stores, grouped by status label, alphabetically sorted per group
- [ ] Tapping a store name in the summary selects it in the dropdown; comment field reflects that store's comment
- [ ] All Store Comments list shows all stores with non-empty comments (any status including neutral)
- [ ] Tapping a comment row selects that store in the dropdown; comment field reflects that store's comment
- [ ] When the comment TextInput is focused, the modal ScrollView scrolls so the field is visible above the keyboard
- [ ] No comment edit modal exists
- [ ] Saving the item persists: non-neutral preferences and neutral+comment rows; excludes neutral+no-comment rows
- [ ] Re-opening the item edit modal reflects saved preferences and comments correctly
- [ ] Warnings (avoided, unavailable, non-preferred) trigger correctly when adding items to the shopping list after saving preferences
