## Feature: Dark Mode Visual Implementation

### Context

This feature implements full light/dark mode support across all app screens and components. The infrastructure (`AppThemeProvider` in `lib/theme.tsx`, Settings toggle, `constants/Colors.ts` token slots) was scaffolded in an earlier pass, but every component uses hardcoded hex values that ignore the theme. This spec covers five changes:

1. **Infrastructure** — expand `lib/theme.tsx` to support a 3-state preference (`system | light | dark`), add `useThemeColors()` hook, and fix the `ThemeProvider` alignment in `app/_layout.tsx`
2. **Color palette** — replace `constants/Colors.ts` with a typed `AppColors` interface and full 18-token light/dark palette
3. **Settings** — replace the binary Switch with three "APPEARANCE" radio rows (System / Light / Dark)
4. **Screen and component migration** — apply `makeStyles(colors) + useMemo` pattern to all ~16 files
5. **Tests** — new theme tests + Settings test updates + global jest mock for `useThemeColors`

Implementation can be delivered in the 5 batches described in the design doc. The feature is not Done until all batches are complete.

**`client/lib/theme.tsx`** — replace the entire file

```typescript
import React, { createContext, useContext, useEffect, useState } from 'react';
import AsyncStorage from '@react-native-async-storage/async-storage';
import { useColorScheme } from '@/components/useColorScheme';
import type { AppColors } from '@/constants/Colors';
import { lightColors, darkColors } from '@/constants/Colors';

export type ThemePreference = 'system' | 'light' | 'dark';

interface AppThemeContextType {
  themePreference: ThemePreference;
  isDark: boolean;
  setThemePreference: (pref: ThemePreference) => void;
}

const STORAGE_KEY = '@app_theme_pref';

const AppThemeContext = createContext<AppThemeContextType | undefined>(undefined);

export const AppThemeProvider: React.FC<{ children: React.ReactNode }> = ({ children }) => {
  const deviceScheme = useColorScheme();
  const [themePreference, setThemePref] = useState<ThemePreference>('system');

  useEffect(() => {
    AsyncStorage.getItem(STORAGE_KEY).then((saved) => {
      if (saved === 'light' || saved === 'dark' || saved === 'system') {
        setThemePref(saved);
      }
    });
  }, []);

  const isDark =
    themePreference === 'system' ? deviceScheme === 'dark' : themePreference === 'dark';

  const setThemePreference = (pref: ThemePreference) => {
    setThemePref(pref);
    AsyncStorage.setItem(STORAGE_KEY, pref);
  };

  return (
    <AppThemeContext.Provider value={{ themePreference, isDark, setThemePreference }}>
      {children}
    </AppThemeContext.Provider>
  );
};

export const useAppTheme = () => {
  const context = useContext(AppThemeContext);
  if (!context) throw new Error('useAppTheme must be used within AppThemeProvider');
  return context;
};

export const useThemeColors = (): { colors: AppColors } => {
  const { isDark } = useAppTheme();
  return { colors: isDark ? darkColors : lightColors };
};
```

Key changes vs. the current file:
- AsyncStorage key changes from `@app_theme` → `@app_theme_pref`
- `toggleTheme()` removed; replaced with `setThemePreference(pref: ThemePreference)`
- `themePreference` (stored value) is now exposed alongside resolved `isDark`
- `useThemeColors()` is a new named export
- `useColorScheme` is imported from `@/components/useColorScheme` (picks up the web stub that returns `'light'`)

### Component Color Migration Pattern

This standard pattern applies to every file in Batches 3–5.

**Step 1 — Imports:**
```typescript
import { useThemeColors } from '@/lib/theme';
import type { AppColors } from '@/constants/Colors';
// Also add useMemo to the React import if not already present
```

**Step 2 — Module-scope style factory** (replaces the module-scope `StyleSheet.create({...})` call):
```typescript
const makeStyles = (colors: AppColors) =>
  StyleSheet.create({
    container: { flex: 1, backgroundColor: colors.background },
    title:     { color: colors.textPrimary, fontSize: 24 },
    // ... replace every hardcoded hex with the appropriate token
  });
```

**Step 3 — Inside the component function:**
```typescript
const { colors } = useThemeColors();
const styles = useMemo(() => makeStyles(colors), [colors]);
```

### Toast.tsx — Special Case

The `Toast` component has two variants with different color semantics:

**Default (dark notification overlay):**
Use an inverted surface effect — `colors.textPrimary` as background and `colors.background` as text color. In light mode this gives a dark bg with white text; in dark mode this gives a near-white bg with dark text. Both contrast well against their respective screen backgrounds.

```typescript
const makeStyles = (colors: AppColors) =>
  StyleSheet.create({
    container: {
      // ... positioning unchanged
      backgroundColor: colors.textPrimary,
    },
    text: {
      color: colors.background,
      fontSize: 14,
      fontWeight: '600',
    },
    warningContainer: {
      // ... positioning unchanged
      backgroundColor: '#fffbeb',   // fixed amber signal color
      borderWidth: 1,
      borderColor: '#fbbf24',       // fixed amber signal color
    },
    warningText: {
      color: '#92400e',             // fixed amber signal color
      fontSize: 14,
      fontWeight: '600',
    },
  });
```

**Warning variant:** Keep `backgroundColor: '#fffbeb'`, `borderColor: '#fbbf24'`, `color: '#92400e'` hardcoded. These are amber semantic signal colors per the design doc decision. The `makeStyles` factory still wraps them, but their values do not come from tokens.

### Platform Considerations

- `useColorScheme` in `lib/theme.tsx` must be imported from `@/components/useColorScheme`, not directly from `react-native`. The web stub (`useColorScheme.web.ts`) always returns `'light'`, so on web, the `system` preference always resolves to light mode. This is acceptable; system dark mode on web would require CSS media queries (out of scope).
- No `Alert.alert` usage is introduced.

### Acceptance Criteria

- Settings → App → Appearance section shows three tappable rows: System, Light, Dark. The active preference shows a `Check` icon on the right. System row shows "Follows device setting" subtitle.
- Tapping a preference row updates the Check immediately. The binary `Switch` is no longer rendered.
- Setting `Dark` → all screens (shopping list, items, history, modals, auth) render with dark backgrounds and light text.
- Setting `Light` → all screens render with light colors regardless of device setting.
- Setting `System` → app follows device dark/light setting.
- The chosen preference is restored on subsequent sessions (AsyncStorage persists across app restarts).
- Navigation chrome (tab bar, nav headers) matches the app theme when dark mode is forced via Settings.
- Store color dots and user avatar colors are unchanged in both modes.
- Warning badge semantic icon colors (amber, red, gray) are unchanged in both modes.
- `testID="settings-dark-mode-switch"` is not rendered in any state.
