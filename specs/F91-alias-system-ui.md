## Feature: Alias System UI

### Context

UI phase of the Token & Item Alias System. F90 delivered the data layer (schema, hooks, parser integration). F91 adds the user-facing screens for managing token aliases and item aliases.

Three surfaces:
1. **Abbreviations screen** — full-screen modal for browsing and editing token aliases (word_aliases table)
2. **Item edit modal sections** — "Also known as" chips for item aliases, "Active Abbreviations" read-only reference, "Define Abbreviations" launch button
3. **Avatar menu entry** — "Abbreviations" as a top-level menu item

Design decisions recorded in `docs/design/F90-token-item-alias-system.md` — UI Design section.

**Depends on:** F90 (data + parser) — must be shipped first. F91 uses hooks from `client/api/aliases.ts` and the extended `MasterItemRef.aliases` field.

- **Add `useWordAliasesForWords` helper** — convenience function that takes a `string[]` of canonical words and a word aliases `Map`, returns a filtered `Map<string, string[]>` of `canonicalWord → [alias1, alias2, ...]`. ### Component Design — Abbreviations Screen

#### `Abbreviations.tsx`

**Props:**
```typescript
interface AbbreviationsProps {
  visible: boolean;
  onClose: () => void;
  initialSearch?: string;  // pre-populated from item edit "Define Abbreviations"
}
```

**Structure:** Full-screen modal (§7b pattern, same as SizesAndPackages/VocabularyManagement).

**State:**
```typescript
const [viewMode, setViewMode] = useState<'canonical' | 'alias'>('canonical');
const [canonicalSearch, setCanonicalSearch] = useState(initialSearch ?? '');
const [aliasSearch, setAliasSearch] = useState('');
const [dialogVisible, setDialogVisible] = useState(false);
const [dialogCanonical, setDialogCanonical] = useState('');
const [dialogCanonicalEditable, setDialogCanonicalEditable] = useState(false);
const [dialogAliases, setDialogAliases] = useState<string[]>([]);
const [dialogNewAliasInput, setDialogNewAliasInput] = useState('');
const [dialogExistingId, setDialogExistingId] = useState<string | null>(null);
```

**Toggle:** Two-segment toggle in the header. Each view has independent search state (`canonicalSearch` vs `aliasSearch`). Toggling preserves each view's search but does NOT cross-populate.

**Data source:** `useWordAliases()` returns `Map<string, string>` (alias → canonical). Reshape for display:
- **Canonical → Aliases view:** Group by canonical word → `Map<string, { id: string; alias: string }[]>`
- **Alias → Canonical view:** Each alias as its own row with its canonical target

**Search (OR semantics, cross-matching):**
- Split search text on whitespace → array of search terms
- A row matches if ANY search term is a prefix of ANY word in the row (canonical word AND alias words in canonical view; alias AND canonical in alias view). The toggle controls display grouping, not search scope.
- Case-insensitive matching
- In canonical view, aliases that prefix-match a search term are highlighted (bold, `#2563eb`) to show why the row matched

**Placeholder rows:**
- After filtering existing rows, check each search term: if no existing row matches that term, add a placeholder row
- In canonical→aliases view: placeholder shows `boneless (no aliases)` with muted styling
- In alias→canonical view: placeholder shows `brth (undefined)` with muted styling
- **Unknown word warning:** If a search term doesn't appear in any master item name or item alias (check `useMasterItemNames` data), the placeholder shows inline amber text: `"xyz" doesn't appear in any of your items`
- Placeholder rows are tappable — they open the edit dialog in "new entry" mode

**Row rendering (FlatList):**
- Canonical→aliases view: `[canonical word]  [alias chip] [alias chip] ...` or `[canonical word]  (no aliases)`
- Alias→canonical view: `[alias]  → [canonical word]`
- Tap opens edit dialog for that canonical word

**Edit dialog (§7a pattern):**

Opens as a centered card modal (transparent backdrop, same as VocabularyManagement dialog):

```
┌──────────────────────────────┐
│ [Delete pill]  chicken    [X]│
│                              │
│ Aliases:                     │
│ [chk ×] [chkn ×]            │
│                              │
│ ┌──────────────────────────┐ │
│ │ Add alias...             │ │
│ └──────────────────────────┘ │
│ ⚠ inline conflict warning    │
│                              │
│ Suggestions: chk  chkn      │
│                              │
│           [Cancel] [Save]    │
└──────────────────────────────┘
```

- **Header:** Delete pill (top-left, Trash2 icon in `#fee2e2` background — only when editing existing), title = canonical word, X close (top-right). Follows §7a modal header pattern.
- **Canonical word field:** Read-only text when editing existing entry. Editable `TextInput` when creating new (from placeholder row or alias→canonical view placeholder).
- **Alias chips:** Existing aliases as removable chips with `×` button. Same chip styling as VocabularyManagement.
- **Text input:** "Add alias..." placeholder. Return key adds as chip. Single-token validation: reject whitespace (must be a single token), lowercase, trim. Punctuation is allowed (e.g. "p.b." for peanut butter). Reject empty after trim.
- **Suggestions section:** Fetch `useAbbreviationSuggestions()` on dialog open. Show suggestions for the canonical word as tappable text buttons. Tap adds as chip (if not already present). Only shown when suggestions exist for this word.
- **Conflict warnings:** Inline text below the input field, live-updating as user types in the alias input:
  - **Blocking (red, `#991b1b`):** "An alias 'chk' already exists (→ chicken)" — check against all word_aliases in the household. Disable Save button when any blocking conflict exists.
  - **Vocabulary conflict (amber, `#f59e0b`):** "'can' is also a package type — alias won't apply in quantity contexts (e.g., '2 cans')" — check the current `vocabulary` data (from `useVocabulary`) for matches in units, packages, or size descriptors (canonical or alias).
  - **Item name conflict (amber, `#f59e0b`):** "'broth' appears in N of your items — this alias will affect how those items are found" — check `useMasterItemNames` data for items containing this word.
  - **Unknown canonical word (amber, `#f59e0b`):** "'xyz' doesn't appear in any of your items" — only for new entries where the canonical word doesn't appear in any master item name or item alias. Shown on the canonical field, not the alias input.
- **Save:** Calls `useCreateWordAlias` for each new alias chip (not in the existing entry), `useDeleteWordAlias` for each removed alias chip. For new entries (no existing ID), creates all aliases. For editing: diff the original aliases against current chips and apply deletes/creates. Note: `word_aliases` has one row per alias (alias → canonical), not one row per canonical word. A canonical word with 3 aliases = 3 rows.
- **Delete:** Deletes all `word_aliases` rows for this canonical word. Uses the inline delete confirmation pattern from VocabularyManagement (confirm container appears, Cancel/Delete buttons).

**Item-launch behavior:** When `initialSearch` prop is provided:
- `canonicalSearch` state starts with the value
- View mode starts as `'canonical'`
- All the item's words appear as rows (existing or placeholder)

### Component Design — Item Edit Modal Sections

#### "Also known as" section (`items.tsx`)

Placed after "Alternate Quantities", before "Store Preferences":

```
Also known as
[Chicken Tenders ×] [Chicken Fingers ×]  [+ Add alias]
```

- **State:** `aliases: string[]` and `newAliasInput: string`, `showAliasInput: boolean`
- **Chips:** Each alias as a removable chip (`×` removes from local state). Same chip pattern as VocabularyManagement aliases.
- **Add:** `+ Add alias` text button at end. Tap toggles `showAliasInput` → shows a `TextInput` inline. Return key adds the trimmed value as a new alias (if non-empty and not duplicate). Blur dismisses without adding.
- **Empty state:** Just the `+ Add alias` button, no "No aliases" text.
- **Save integration:** `aliases` array is included in the `payload` object passed to `useUpdateMasterItem` (and in `oldSnapshot` for undo). For new items, `aliases` defaults to `[]`.

#### "Active Abbreviations" section (`items.tsx`)

Placed after "Also known as", only shown when `editingItem` is not null:

```
Active Abbreviations
chicken → chk, chkn
breast → brst, bst
```

- **Data:** Extract unique lowercase words from `editingItem.name` and `aliases` state. For each word, look up in the `wordAliases` Map (from `useWordAliases`) — collect all aliases that map to that canonical word. Reverse the Map: build `canonical → alias[]` from the `alias → canonical` Map.
- **Rendering:** One `<Text>` row per word that has aliases: `"{word} → {alias1}, {alias2}"`. Read-only, no tap behavior.
- **Empty state:** `"No abbreviations defined for this item's words"` in muted text.

#### "Define Abbreviations" button (`items.tsx`)

Below the Active Abbreviations section:

```
[Define Abbreviations]
```

- Blue text button (`#2563eb`), no background
- Tap sets `abbreviationsVisible: true` and `abbreviationsInitialSearch` to the item's words joined by spaces
- `<Abbreviations visible={abbreviationsVisible} onClose={() => setAbbreviationsVisible(false)} initialSearch={abbreviationsInitialSearch} />` rendered conditionally
- When the Abbreviations screen closes, the Active Abbreviations section refreshes automatically (React Query invalidation from CRUD mutations triggers re-render)
