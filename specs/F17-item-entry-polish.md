## Feature: Item Entry Flow Polish

### Context

This spec batches four related issues that all touch the item add/edit flow:

| Issue | Summary |
|-------|---------|
| #63 | One-off edit modal silently creates a master item on save |
| #59 | Quick "Add (One-time)" tap always adds qty='1' — no way to pick a quantity |
| #60 | In-list edit dialog shows only a plain TextInput for qty — no alternate qty chips |
| #65 | One-off items default to `categories[0]` instead of null/no department |

All changes are in `SmartAddItem.tsx`, `index.tsx`, `list.ts`, and `items.tsx`. No schema changes. No new patterns — all UI is an extension of the inline pill row (F15), qty chip section (SmartAddItem modal), and tag chip (items.tsx) patterns already established.

### Files to Modify

#### 1. `client/components/SmartAddItem.tsx`

**#63 — One-off edit modal: two-button action row for one-off path**

The modal action row currently always shows: `[Cancel] [Add to List]`. For one-off items (`!selectedItem?.id`), `onSaveEdited` silently calls `createMasterItem`. Fix by splitting the action row:

- When `selectedItem?.id` **exists** (master item): unchanged — `[Cancel] [Add to List]` where "Add to List" calls `onSaveEdited`.
- When `selectedItem?.id` **is null** (one-off): `[Cancel] [Add to List] [Save to Master & Add]`
  - **"Add to List"** (primary, blue): new `onOneOffEditAdd()` function — calls `addItem` with `item_id: null`, `quantity: editQty`, `store_id: editStoreId || null`, `category_id: editCategoryId || null`. Registers undo with label `Added {name}`. Calls `clearAndClose()`.
  - **"Save to Master & Add"** (secondary, gray): existing `onSaveEdited()` logic unchanged — calls `createMasterItem` then `addItem`.

Button styling for the new secondary "Save to Master & Add":
- Use existing `cancelBtn` style (gray background) with `cancelText` style (dark text).
- The three buttons remain in the right-justified compact action row (`styles.modalActions`): `[Cancel] [Add to List] [Save to Master & Add]`.

**#59 — Qty selection on the one-off create row**

Add a `oneOffQty` state (default `'1'`) and a `oneOffQtyPopoverOpen` boolean state.

Restructure `styles.createMain` from a `TouchableOpacity` to a plain `View`, and wrap only the "Add..." text in its own `TouchableOpacity` (so chip taps don't bubble up to the add action).

Inside the restructured `createMain`, below the text, add an inline pill row with:
- `"1"` chip — active (blue) when `oneOffQty === '1'`; tapping sets `oneOffQty = '1'`
- `"Other"` chip — active (blue) when `oneOffQty !== '1'` and shows the custom value as label (same as master item "Other" chip behavior); tapping opens `oneOffQtyPopoverOpen`

When `oneOffQtyPopoverOpen` is true, render a `styles.otherQtyPopover` below the pill row (same positioned View + TextInput pattern as the master item "Other" popover, with `autoFocus`, `returnKeyType="done"`, placeholder `"e.g. 3 lbs"`). On submit: if value is non-empty, set `oneOffQty`; close popover.

Update `onOneOffAdd()` to use `oneOffQty` instead of hardcoded `'1'`.

Update `clearAndClose()` to reset `oneOffQty = '1'` and `oneOffQtyPopoverOpen = false`.

**#65 — Fix category defaults for one-off path**

`onEditAdd` currently: `setEditCategoryId(item.default_category_id || metadata?.categories?.[0]?.id || '')`.
Fix: `setEditCategoryId(item.default_category_id || '')`.
For master items, `item.default_category_id` is a real value. For one-off items `{ name: query, id: null }`, `default_category_id` is `undefined`, so this correctly defaults to `''` (null).

`onOneOffAdd` currently: `category_id: metadata?.categories?.find((category) => category.name === 'Other')?.id`.
Fix: `category_id: null`.

`onSaveEdited` line with `default_category_id: editCategoryId`:
Fix: `default_category_id: editCategoryId || null`.

#### 2. `client/app/(tabs)/index.tsx`

**#60 — Qty chips in in-list edit modal**

Add state: `editQtyChips: string[]` (array of quick-select qty values for the currently editing item).

In `openEditModal(item: ListItem)`: compute chip list from the master item data available on the list row:
```typescript
const masterDefaultQty = item.master_item?.default_qty ?? null;
const masterAltQtys = item.master_item?.alternate_qtys ?? [];
const chips = masterDefaultQty
  ? [masterDefaultQty, ...masterAltQtys]
  : masterAltQtys;
setEditQtyChips(chips);
```
For one-off items (`item.item_id === null`), `master_item` is null — `editQtyChips` will be `[]`.

In the edit modal `ScrollView`, after the `Quantity` TextInput, add a chip section (only when `editQtyChips.length > 0`):
```tsx
{editQtyChips.length > 0 && (
  <View style={{ marginBottom: 16 }}>
    <Text style={styles.label}>Usual Quantities</Text>
    <View style={styles.tagsContainer}>
      {editQtyChips.map((chip) => (
        <TouchableOpacity
          key={chip}
          onPress={() => setEditQty(chip)}
          style={[styles.tag, editQty === chip ? styles.tagActive : styles.tagInactive]}
        >
          <Text style={editQty === chip ? styles.tagTextActive : styles.tagTextInactive}>
            {chip}
          </Text>
        </TouchableOpacity>
      ))}
    </View>
  </View>
)}
```
Use existing `styles.tagsContainer`, `styles.tag`, `styles.tagActive`, `styles.tagInactive`, `styles.tagTextActive`, `styles.tagTextInactive` from index.tsx (they already exist, matching SmartAddItem's edit modal pattern).

### Acceptance Criteria

**#63 — One-off edit two-button layout:**
- [ ] Tapping chevron on the one-off row ("Add "X" (One-time)") opens the edit modal
- [ ] The modal action row shows three buttons: "Cancel", "Add to List", "Save to Master & Add"
- [ ] "Add to List" adds the item with `item_id: null` (one-off, not saved to master)
- [ ] "Save to Master & Add" creates a master item and adds it linked (`item_id` set)
- [ ] Tapping chevron on a **master item** result still shows two buttons only: "Cancel", "Add to List"

**#59 — One-off qty selection:**
- [ ] The create row for one-off items shows a "1" chip and an "Other" chip below the "Add "X" (One-time)" text
- [ ] The "1" chip is active (blue) by default
- [ ] Tapping "Other" opens a freeform qty input popover
- [ ] Typing a custom qty and pressing Return sets it as the active chip label and closes the popover
- [ ] Tapping "Add "X" (One-time)" adds the item with the currently selected qty (not always '1')
- [ ] Clearing the query resets qty back to '1'

**#60 — In-list edit qty chips:**
- [ ] Long-pressing a master item (with `item_id` and `default_qty`/`alternate_qtys`) opens the edit modal showing a "Usual Quantities" chip section below the qty TextInput
- [ ] Tapping a chip sets the qty TextInput to that value
- [ ] One-off items (no `item_id`) show no chips — only the plain TextInput
- [ ] Items with no `alternate_qtys` but a `default_qty` show one chip

**#65 — Null category defaults:**
- [ ] Tapping "Add "X" (One-time)" quick-add adds the item with `category_id: null`
- [ ] Opening the edit modal for a one-off item does not pre-select any category (editCategoryId is `''`)
- [ ] Creating a new master item in the Items screen does not pre-select any category
- [ ] The Items screen category picker has a "None" chip as the first option
- [ ] "None" chip is active when no category is selected; tapping it clears the category selection
- [ ] Saving an item with "None" selected stores `default_category_id: null` (not empty string)
- [ ] Items with null category display "Uncategorized" in the Items screen list row (already implemented via `|| 'Uncategorized'` in items.tsx)

### Deferred Items

- **SmartAddItem edit modal category picker**: The SmartAddItem edit modal does not currently show a category picker. Adding one (with "None" option) is a useful follow-on but is not in scope for this spec — the #65 fix is to stop defaulting to `categories[0]`, not to surface the picker.
- **One-off "Other" chip popover + F14 coordination**: The free-form text popover for one-off qty (#59) uses freeform input. F14 (free-form input parsing to extract name + qty from typed text) would overlap with this. For now, the popover is a standalone qty input — F14 can post-process the main search bar text independently.
- **Null-category grouping on shopping list**: Items with null category display fine on the shopping list (not grouped by category, only by store). If a future feature groups items by category within a store section, null grouping will need design. Deferred.
