## Feature: Voice Input Parser Normalization

### Context

Voice typing (and manual input) can produce natural-language forms that the parser doesn't recognize today. This feature adds a **pre-parse normalization function** that transforms voice-style input into the parser's expected syntax:

1. **Word-to-number normalization:** "two pounds ground beef" → "2 pounds ground beef"
2. **"at" keyword as store hint:** "chicken at Safeway" → "chicken @Safeway"

Both transformations run before `tokenize()` so the entire existing parser pipeline benefits transparently. The normalization function is pure and testable independently.

Related: GitHub issue #94. Design decisions recorded in `docs/design/F44-freeform-input-parsing.md` (store hint behavior). The "at" keyword extends the existing `@` store hint pattern — no new UI patterns are needed.

### Files to Modify

#### `client/lib/parser.ts`
- Add a new exported function `normalizeVoiceInput(input: string, storeNames: string[]): string` near the top of the file (before `tokenize`)
- This function applies two transformations in order:
  1. **Word-to-number replacement:** Replace word-form numbers with digit equivalents using a lookup table (case-insensitive, whole-word boundaries only)
  2. **"at" → "@" store hint:** When a token matches "at" (case-insensitive) and the *next* token is a case-insensitive prefix of any entry in `storeNames`, replace "at X" with "@X" in the output
- The function operates on the raw input string and returns a transformed string
- **Implementation detail for "at" detection:** Split input on whitespace, scan for "at" tokens. When found, check if the next token is a prefix (case-insensitive, minimum 1 char) of any store name. If yes, replace "at nextToken" with "@nextToken". If no store matches, leave "at" as-is (it becomes a NAME token, which is correct — e.g., someone might have an item with "at" in the name)

#### `client/components/SmartAddItem.tsx`
- Import `normalizeVoiceInput` from `@/lib/parser`
- In the `parseResult` memo (line ~141), call `normalizeVoiceInput(query, storeNamesList)` before passing to `parseInput`
- In the `parseCandidate` memo (line ~145), also normalize the query before passing to `tokenize`
- Add a `storeNamesList` memo that extracts store names from `metadata?.stores`:
  ```typescript
  const storeNamesList = useMemo(() => {
    return (metadata?.stores || []).map((s) => s.name);
  }, [metadata?.stores]);
  ```
- **Important:** `parseResult.rawInput` must remain the **original** un-normalized query (used for "Add as one-off" display text). The `parseInput` function already sets `rawInput` from its `input` parameter. To preserve the original: either pass the original query separately, or set `rawInput` after the call. The cleanest approach: leave `parseInput` unchanged and override `rawInput` after:
  ```typescript

    const normalized = normalizeVoiceInput(query, storeNamesList);
    const result = parseInput(normalized, vocab, masterItemNames, wordAliases);
    return { ...result, rawInput: query };
  }, [query, vocab, masterItemNames, wordAliases, storeNamesList]);
  ```

### Word-to-Number Lookup Table

The lookup table is a constant defined in `parser.ts` (module-level, not exported). It maps lowercase word forms to their string digit equivalents:

**Cardinals:**
| Word | Value |
|------|-------|
| zero | 0 |
| one | 1 |
| two | 2 |
| three | 3 |
| four | 4 |
| five | 5 |
| six | 6 |
| seven | 7 |
| eight | 8 |
| nine | 9 |
| ten | 10 |
| eleven | 11 |
| twelve | 12 |

**Fractions:**
| Word | Value |
|------|-------|
| half | 0.5 |
| quarter | 0.25 |

**Multipliers:**
| Word | Value |
|------|-------|
| dozen | 12 |

**Replacement rules:**
- Case-insensitive, whole-word match only (word boundaries — not substrings: "attend" must not become "2tend")
- Replace the word with its digit string: "two" → "2", "half" → "0.5"
- "a dozen" → "1 dozen" is NOT handled here — the word "a" is too ambiguous. The parser's existing COUNT logic handles bare "dozen" → 12 as a number token. (If "a" normalization is wanted, it's a separate future item.)
- Process left-to-right, one pass. Each word is looked up independently.

### "at" Store Hint Logic

**Algorithm:**
1. Split input on whitespace into words (preserving original casing and position)
2. Iterate through words. When a word matches "at" (case-insensitive):
   a. Check if there is a next word
   b. Check if that next word is a case-insensitive prefix of any store name in `storeNames`
   c. If yes: replace "at" with "@" prepended to the next word (remove the space), skip the next word
   d. If no: leave "at" unchanged
3. Reconstruct the string from the (possibly modified) words

**Edge cases:**
- "at" at end of input → no next word → leave as-is
- "at" with no matching store → leave as-is (becomes NAME token)
- "at at" where second "at" matches a store named "Atkins" → first "at" becomes "@at" (unlikely but consistent)
- Input with `@` sigil AND "at" keyword → both work independently; `@` is handled by tokenizer, "at" by normalization
- Quoted strings: normalization operates on raw text before tokenization, so `"at safeway"` inside quotes would be affected. This is acceptable — quoted strings are rare in voice input. If this becomes an issue, a future fix can skip quoted regions.

### Acceptance Criteria

1. Typing "two pounds ground beef" produces the same parse result as "2 pounds ground beef" (count=2, unit=lb recognized)
2. Typing "three cans chicken broth" produces count=3, package=can, name="Chicken Broth"
3. Typing "half pound salmon" produces count=0.5, unit=lb
4. Typing "dozen eggs" produces count=12
5. Typing "milk at Safeway" produces `storeHint: "Safeway"` and Safeway store pill is shown (same as "milk @safeway")
6. Typing "2 lbs chicken at Costco" produces count=2, unit=lb, storeHint: "Costco"
7. Typing "chicken at nonexistent" leaves "at" as a NAME token (no store match → no transformation)
8. The one-off "Add" row displays the original input text (not the normalized form)
9. Words like "attend", "quarter-pounder" are not corrupted by normalization (whole-word boundaries)
10. Typing "milk at saf" matches "Safeway" via prefix (same as "@saf")
