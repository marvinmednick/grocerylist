## Feature: Smart Entry Model

### Context

Replace per-item store selection with an always-active store context that determines where items are added. Replace `items.default_store_id` and the `item_stores` table with a richer `item_store_preferences` table supporting preferred/avoided/unavailable status per store. Make stores household-scoped with a creation UI. Generate warnings at add time and write them to `list_items.warnings`.

Design decisions recorded in `docs/design/F12-smart-entry-model.md`.

**F13 dependency:** F13 (List Display Density & Warnings) has already implemented the warning *display* layer — `WarningBadge` component, amber warning toast variant, warning preferences Settings UI, and the `list_items.warnings` / `profiles.warning_preferences` schema columns. F12 *populates* the warnings JSONB at add time; F13 renders it. Do not modify F13's display components.

**CODING.md note:** CODING.md references `default_store_id` and `item_stores` which this feature removes. Follow this spec; CODING.md will be updated post-implementation.

### Database / Schema Changes

**Migration file:** `supabase/migrations/20250101000011_f12_smart_entry_model.sql`

```sql
-- F12: Smart Entry Model

-- ============================================================
-- 1. Make stores household-scoped
-- ============================================================

-- Add nullable first, backfill, then set NOT NULL
ALTER TABLE stores ADD COLUMN household_id UUID REFERENCES households(id) ON DELETE CASCADE;

-- Assign all existing stores to the default household
UPDATE stores SET household_id = (SELECT id FROM households LIMIT 1);

ALTER TABLE stores ALTER COLUMN household_id SET NOT NULL;

-- Update unique constraint: name is unique per household, not globally
ALTER TABLE stores DROP CONSTRAINT stores_name_key;
ALTER TABLE stores ADD CONSTRAINT stores_name_household_unique UNIQUE (name, household_id);

CREATE INDEX stores_household_idx ON stores(household_id);

-- Replace global read policy with household-scoped policies
DROP POLICY "Public read stores" ON stores;

CREATE POLICY "Household members can read stores" ON stores
    FOR SELECT TO authenticated
    USING (household_id = get_my_household_id());

CREATE POLICY "Household members can insert stores" ON stores
    FOR INSERT TO authenticated
    WITH CHECK (household_id = get_my_household_id());

CREATE POLICY "Household members can update stores" ON stores
    FOR UPDATE TO authenticated
    USING (household_id = get_my_household_id());

CREATE POLICY "Household members can delete stores" ON stores
    FOR DELETE TO authenticated
    USING (household_id = get_my_household_id());

-- ============================================================
-- 2. Create item_store_preferences table
-- ============================================================

CREATE TABLE item_store_preferences (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    item_id UUID NOT NULL REFERENCES items(id) ON DELETE CASCADE,
    store_id UUID NOT NULL REFERENCES stores(id) ON DELETE CASCADE,
    status TEXT NOT NULL CHECK (status IN ('preferred', 'avoided', 'unavailable')),
    comment TEXT,
    household_id UUID NOT NULL REFERENCES households(id) ON DELETE CASCADE,
    UNIQUE (item_id, store_id)
);

CREATE INDEX item_store_preferences_item_idx ON item_store_preferences(item_id);
CREATE INDEX item_store_preferences_household_idx ON item_store_preferences(household_id);

ALTER TABLE item_store_preferences ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Household members can manage item_store_preferences" ON item_store_preferences
    FOR ALL TO authenticated
    USING (household_id = get_my_household_id())
    WITH CHECK (household_id = get_my_household_id());

-- ============================================================
-- 3. Migrate data from item_stores to item_store_preferences
-- ============================================================

-- Migrate preferred item_stores rows
INSERT INTO item_store_preferences (item_id, store_id, status, household_id)
SELECT item_id, store_id, 'preferred', household_id
FROM item_stores
WHERE is_preferred = true;

-- Migrate items.default_store_id as preferred (if not already covered by item_stores)
INSERT INTO item_store_preferences (item_id, store_id, status, household_id)
SELECT id, default_store_id, 'preferred', household_id
FROM items
WHERE default_store_id IS NOT NULL
  AND NOT EXISTS (
    SELECT 1 FROM item_store_preferences isp
    WHERE isp.item_id = items.id AND isp.store_id = items.default_store_id
  );

-- ============================================================
-- 4. Drop old structures
-- ============================================================

DROP TABLE item_stores;

ALTER TABLE items DROP COLUMN default_store_id;
```

**Also update `supabase/full_schema.sql`** to reflect the new schema state (stores with `household_id`, `item_store_preferences` table replacing `item_stores`, items without `default_store_id`, updated RLS policies and constraints).

### Undo/Redo Registration

**Active store changes:** No undo (navigation context, not data mutation).

**Adding items:** Existing undo pattern unchanged. `pushAction` call in SmartAddItem stays the same; warnings are included in the insert/delete payload automatically.

**Store creation:** No undo (too complex to reverse — would need to handle FK references).

**Item save with preferences (items.tsx):** Register undo when saving master item edits. Switch from `mutate` to `mutateAsync` in `handleSave`. Capture snapshot of item + preferences before save:

```typescript
// Before save — capture old state
const oldPrefs = editingItem.item_store_preferences || [];
const oldSnapshot = {
  name: editingItem.name,
  short_name: editingItem.short_name,
  default_qty: editingItem.default_qty,
  alternate_qtys: editingItem.alternate_qtys,
  default_category_id: editingItem.default_category_id,
  store_preferences: oldPrefs.map(p => ({
    store_id: p.store_id, status: p.status, comment: p.comment
  })),
};

// After save:
pushAction({
  label: `Edited ${name}`,
  undo: async () => {
    await updateItem({ id: editingItem.id, ...oldSnapshot });
  },
  redo: async () => {
    await updateItem({ id: editingItem.id, ...newPayload });
  },
});
```

### Acceptance Criteria

1. The shopping list header shows the active store name (in the store's color) with a ▾ chevron instead of "Shopping List"
2. Tapping the store name opens a dropdown listing all household stores with color dots; active store has a checkmark
3. Selecting a store from the dropdown changes the active store; persists across app restarts (AsyncStorage)
4. "+ Add new store" in the dropdown opens a creation modal with name + color picker
5. Created stores appear in the dropdown and become the active store
6. Stores are household-scoped: different households see different stores
7. Quick-adding an item places it in the active store's section (not the item's old default store)
8. One-off items use the active store
9. Edit-before-add modal defaults to the active store (can be changed by user)
10. Store pills are removed from the SmartAddItem dropdown rows
11. When adding a master item to an avoided store, a warning is generated with `type: "avoided"` and the comment (if any)
12. When adding to an unavailable store, a warning with `type: "unavailable"` is generated
13. When adding to a non-preferred store (and preferred stores exist), a warning with `type: "non_preferred"` is generated with the preferred store names
14. When adding with a non-standard quantity, a warning with `type: "non_standard_qty"` is generated
15. Warnings appear as badges on list items (rendered by F13's `WarningBadge`)
16. Items tab edit modal shows a status selector per store: Neutral / Preferred / Avoided / Unavailable
17. Comment field appears below status selector for non-neutral statuses
18. Saving item edits with preference changes registers an undo action
19. The `item_stores` table no longer exists; `default_store_id` column is removed from `items`
20. `item_store_preferences` table stores per-item per-store status and optional comment

### Warning Computation Logic

Export a `computeWarnings` function from `client/api/items.ts`:

```typescript
export interface Warning {
  type: 'avoided' | 'unavailable' | 'non_preferred' | 'non_standard_qty';
  store_id?: string;
  store_name?: string;
  comment?: string | null;
  preferred_stores?: string[];
  entered?: string;
  standard?: string[];
}

export function computeWarnings(
  preferences: ItemStorePreference[] | undefined,
  activeStoreId: string | null,
  quantity: string,
  defaultQty: string | null,
  alternateQtys: string[] | null,
): Warning[] {
  const warnings: Warning[] = [];
  if (!activeStoreId) return warnings;

  if (preferences && preferences.length > 0) {
    // Check active store status
    const activePref = preferences.find(p => p.store_id === activeStoreId);
    if (activePref?.status === 'avoided') {
      warnings.push({
        type: 'avoided',
        store_id: activeStoreId,
        store_name: activePref.store?.name,
        comment: activePref.comment,
      });
    } else if (activePref?.status === 'unavailable') {
      warnings.push({
        type: 'unavailable',
        store_id: activeStoreId,
        store_name: activePref.store?.name,
        comment: activePref.comment,
      });
    }

    // Check non-preferred
    const preferredStores = preferences.filter(p => p.status === 'preferred');
    if (preferredStores.length > 0) {
      const isActivePreferred = preferredStores.some(p => p.store_id === activeStoreId);
      if (!isActivePreferred) {
        warnings.push({
          type: 'non_preferred',
          preferred_stores: preferredStores.map(p => p.store?.name).filter(Boolean),
        });
      }
    }
  }

  // Check non-standard qty (applies to master items only)
  if (quantity && defaultQty) {
    const standardQtys = [defaultQty, ...(alternateQtys || [])];
    if (!standardQtys.includes(quantity)) {
      warnings.push({
        type: 'non_standard_qty',
        entered: quantity,
        standard: standardQtys,
      });
    }
  }

  return warnings;
}
```

SmartAddItem calls this before each add and includes the result in the `addItem` payload:
```typescript
const warnings = computeWarnings(
  item.item_store_preferences,
  activeStoreId,
  selection.qty,
  item.default_qty,
  item.alternate_qtys,
);
await addItem({ ...payload, warnings });
```
