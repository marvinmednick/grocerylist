## Feature: Store Dropdown in Edit Modals

### Context

The "Add Detail" modal in `SmartAddItem.tsx` and the "Edit Item" modal in `app/(tabs)/index.tsx` both present store selection as a row of pill buttons. When many stores exist, pills wrap across multiple lines and consume vertical space. This feature replaces those pills with an in-document dropdown — consistent with the store preference dropdown already in `app/(tabs)/items.tsx` (introduced in F16).

The dropdown pattern is established in ui-guidelines.md §13 ("Store: dropdown picker pre-filled with known stores for the item") and in the F16 decision log entry.

This feature also brings both modals into compliance with the established dialog modal pattern (ui-guidelines.md §7a and CODING.md §7):

1. **Safe-area insets** — both modals currently lack `useSafeAreaInsets()` on their outermost containers. At minimum `paddingTop: insets.top` must be applied. `paddingBottom: insets.bottom` should be applied to the action row container when it sits at the bottom edge.

2. **Cancel button in SmartAddItem** — the "Add Detail" modal's master-item path has no Cancel action. A Cancel button must be added to the action row alongside the existing Add/Save button, matching the pattern in `items.tsx` and `index.tsx` (gray button, `style: modalActions`, right-justified).

### UI Spec

Replace the entire store pills block (the `<Text style={styles.label}>Store</Text>` + `<View style={styles.tagsContainer}>...pills...</View>`) in both files with the following structure:

```tsx
<Text style={styles.label}>Store</Text>
<View style={{ marginBottom: 24 }}>
  <TouchableOpacity
    testID="edit-store-dropdown-trigger"
    style={styles.dropdownTrigger}
    onPress={() => setEditStoreDropdownOpen((prev) => !prev)}
  >
    <View style={styles.dropdownValue}>
      {editStoreId ? (
        <>
          <View
            style={[
              styles.storeColorDot,
              { backgroundColor: metadata?.stores?.find((s) => s.id === editStoreId)?.color_code ?? '#9ca3af' },
            ]}
          />
          <Text style={styles.storeNameText}>
            {metadata?.stores?.find((s) => s.id === editStoreId)?.name ?? ''}
          </Text>
        </>
      ) : (
        <Text style={styles.dropdownPlaceholder}>No store</Text>
      )}
    </View>
    <ChevronDown size={16} color="#6b7280" />
  </TouchableOpacity>

  {editStoreDropdownOpen ? (
    <View style={styles.dropdownMenu}>
      {/* "No store" option — always first */}
      <TouchableOpacity
        testID="edit-store-option-none"
        style={styles.dropdownOption}
        onPress={() => {
          setEditStoreId('');
          setEditStoreDropdownOpen(false);
        }}
      >
        <Text style={[styles.storeNameText, { color: '#9ca3af' }]}>— No store —</Text>
      </TouchableOpacity>
      {metadata?.stores?.map((store) => (
        <TouchableOpacity
          key={store.id}
          testID={`edit-store-${store.id}`}
          style={styles.dropdownOption}
          onPress={() => {
            setEditStoreId(store.id);
            setEditStoreDropdownOpen(false);
          }}
        >
          <View style={[styles.storeColorDot, { backgroundColor: store.color_code }]} />
          <Text style={styles.storeNameText}>{store.name}</Text>
        </TouchableOpacity>
      ))}
    </View>
  ) : null}
</View>
```

**Note on existing testIDs**: The existing pill testIDs are `edit-store-${store.id}` in SmartAddItem. The dropdown options reuse the same testID format so existing test mocks (if any) continue to match. A new `edit-store-dropdown-trigger` testID is added for the trigger button.

### Acceptance Criteria

- The "Add Detail" modal in SmartAddItem shows a single-line dropdown trigger for Store, not pills
- The "Edit Item" modal in index.tsx shows a single-line dropdown trigger for Store, not pills
- Tapping the trigger opens a dropdown listing all stores (with color dot) plus a "— No store —" option at the top
- Tapping a store selects it (trigger updates to show its name and color dot) and closes the dropdown
- Tapping "— No store —" clears the selection (trigger shows muted "No store" text) and closes the dropdown
- Tapping the trigger again while open closes the dropdown without changing the selection
- The dropdown flows in-document inside the modal ScrollView (no overflow clipping; the scroll accommodates it)
- Pre-existing save/add behavior is unchanged — store selection is passed through identically to before
- Both modals apply safe-area insets (`paddingTop: insets.top`) on the outermost content container
- The "Add Detail" modal in SmartAddItem has a Cancel button in the action row that dismisses the modal and resets form state
