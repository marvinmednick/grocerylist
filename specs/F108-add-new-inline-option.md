## Feature: Add New as Inline Duplicate Option

### Context

The duplicate resolution dialog (`DuplicateResolutionDialog.tsx`) currently places "Add New" in the bottom row alongside Custom and Cancel, visually separated from the combine options above. This feature moves "Add a separate…" into the options list as a full-width vertical button, making it a peer of the combine actions. The bottom row retains only Custom and Cancel.

All four dialog states are affected: `active-same-store`, `active-different-store`, `purchased-same-trip`, `purchased-other-user`.

---

### Files to Modify

**`client/components/DuplicateResolutionDialog.tsx`**

1. **Remove the `showCombine` variable.** Replace with `showOptions` (always true when not in custom mode) and a separate `showCombineOptions` flag for whether combine buttons should be included:
   ```ts
   const showOptions = !customMode;
   const showCombineOptions = !!combineOptions && combineOptions.length > 0 && duplicateState.startsWith('active-');
   ```

2. **Compute `addSeparateLabel`** (pure `useMemo` or inline, no external helper needed):
   | Condition | Label |
   |-----------|-------|
   | `duplicateState` starts with `purchased-` | `"Add a separate [qty] item"` or `"Add a separate item"` if qty empty |
   | `active-different-store` and `incomingStoreName` present | `"Add a separate [qty] at [incomingStoreName]"` or `"Add a separate item at [incomingStoreName]"` if qty empty |
   | All other cases (active-same-store, active-different-store without store name) | `"Add a separate [qty] item"` or `"Add a separate item"` if qty empty |

   Where `[qty]` = ` ${incomingQuantity}` when `incomingQuantity` is non-empty, otherwise omit.

3. **Restructure the JSX options section.** When `showOptions`, render a single `<View style={styles.optionsList}>` containing:
   - If `showCombineOptions` and `duplicateState === 'active-same-store'`: for each option, one full-width `<TouchableOpacity>` with label `"Combine as ${option.label}"`, calling `onCombine(option)`.
   - If `showCombineOptions` and `duplicateState === 'active-different-store'`: for each option, two full-width buttons:
     - `"Combine as ${option.label} at ${existingStoreName}"` → `onCombine(option, match?.store_id ?? null)`
     - If `incomingStoreId`: `"Combine as ${option.label} at ${incomingStoreName ?? 'target store'}"` → `onCombine(option, incomingStoreId)`
   - Always: one full-width `<TouchableOpacity testID="duplicate-add-separate">` with `addSeparateLabel`, calling `onAddNew`.

4. **Update the bottom row.** Remove the "Add New" button. Retain only `Custom` and `Cancel`:
   ```jsx
   <View style={styles.bottomRow}>
     <TouchableOpacity testID="duplicate-custom" style={styles.actionButton} onPress={() => setCustomMode(true)}>
       <Text style={styles.actionButtonText}>Custom</Text>
     </TouchableOpacity>
     <TouchableOpacity testID="duplicate-cancel" onPress={handleDismiss}>
       <Text style={styles.cancelText}>Cancel</Text>
     </TouchableOpacity>
   </View>
   ```

5. **Remove the `sectionLabel` and associated JSX** ("Combine as:" heading). No section header is rendered above the options list.

6. **Update styles:**
   - **Add** `optionsList: { gap: 8, marginBottom: 16 }` for the vertical option button container.
   - **Remove** `combineRow`, `crossStoreActions`, `crossStoreRow`, `sectionLabel` — no longer used.
   - **Keep** `actionButton`, `section`, `bottomRow`, and all others unchanged.

### Acceptance Criteria

- For `active-same-store`: combine options appear as `"Combine as [qty]"` full-width buttons (one per option); `"Add a separate [qty] item"` appears below them in the same vertical list.
- For `active-different-store`: each combine option produces two full-width buttons — `"Combine as [qty] at [existing store]"` and `"Combine as [qty] at [incoming store]"`; `"Add a separate [qty] at [incoming store]"` appears below.
- For `purchased-same-trip` / `purchased-other-user`: no combine buttons; only `"Add a separate [qty] item"` appears in the options list.
- When `incomingQuantity` is empty, labels fall back to `"Add a separate item"` (and `"Add a separate item at [store]"` for cross-store).
- The "Combine as:" section header is not rendered in any state.
- The bottom row contains only `Custom` and `Cancel`; "Add New" text does not appear anywhere.
- Tapping the "Add a separate…" button calls `onAddNew`.
- Tapping a combine button calls `onCombine` with the correct option and store ID (unchanged behavior).
- Custom mode behavior is unchanged.
