## Feature: Warning System Improvements

### Context

Four issues were batched into F18. Three are implemented here; #50 (WarningBadge -300px overlay fix) is deferred — see Deferred Items.

**Modal naming used throughout this spec:**

| Name | What it is | File |
|------|-----------|------|
| **Add Detail modal** | Edit-before-adding modal in SmartAddItem; opens via `›` chevron | `SmartAddItem.tsx` |
| **List Edit modal** | Edit modal in index.tsx; opens via long-press on a shopping list item | `app/(tabs)/index.tsx` |
| **Master Item modal** | Full item management modal in the Items tab | `app/(tabs)/items.tsx` |

**Issues addressed:**

- **#47** — `WarningBadge.tsx` defines its own `Warning` type that duplicates the canonical one in `api/items.ts`. Remove the duplicate; import from the canonical source. Also move `getWarningText` to `api/items.ts` so both badge and toast can share it.
- **#68** — When a user opens the **Add Detail modal** or **List Edit modal**, inline warnings for the current store/qty selection should be visible. Warnings are computed reactively as the user changes store or qty. No warnings in the Master Item modal (that's where preferences are *defined*, not evaluated).
- **#69** — After any add that produces warnings, a `variant='warning'` toast should fire if the user's `warning_preferences` for that warning type is `toast_and_badge`. The toast fires regardless of whether the user already saw the inline warning in a modal.

Design decisions recorded here in the spec; no separate design doc required for this batch.

### Files to Modify

1. **`client/api/items.ts`**
   - Export `getWarningText(warning: Warning): string` (move from WarningBadge — identical logic)
   - Add `useItemById(itemId: string | null)` hook

2. **`client/api/list.ts`**
   - Update `ListItem.warnings` type from the loose inline type to `Warning[]` (imported from `api/items`)

3. **`client/components/WarningBadge.tsx`**
   - Remove the local `Warning` interface (lines 5–13)
   - Import `Warning` and `getWarningText` from `@/api/items`
   - Remove the local `getWarningText` function

4. **`client/components/SmartAddItem.tsx`**
   - Add `onWarningToast?: (message: string) => void` prop
   - Add `useMyProfile()` call (from `@/api/profile`)
   - Render `<WarningCallout>` inside the Add Detail modal, below the title, above the ScrollView — computed from `selectedItem.item_store_preferences`, `editStoreId`, and `editQty` (master items only; one-off items show nothing)
   - In `onCommitAdd`: after the add, check warnings against `warningPrefs` and call `onWarningToast` if any warning type maps to `toast_and_badge`
   - In `onSaveEdited`: same toast check (warnings are already computed for the `addItem` call)
   - `onOneOffAdd` and `onOneOffEditAdd`: no master item preferences, skip toast check

5. **`client/app/(tabs)/index.tsx`**
   - Add `useItemById(editingItem?.item_id ?? null)` — enabled only when the List Edit modal is open and the item has a master item link
   - Render `<WarningCallout>` inside the List Edit modal, below the title, above the ScrollView — computed from fetched item's `item_store_preferences`, `editStoreId`, and `editQty` (master-linked items only)
   - Extend `toast` state: `{ visible: boolean; message: string; variant: 'default' | 'warning' }` (default: `variant: 'default'`)
   - Pass `variant={toast.variant}` to `<Toast>`
   - Pass `onWarningToast` callback to `<SmartAddItem>`: sets `toast` with `variant: 'warning'`

### New Files

1. **`client/components/WarningCallout.tsx`**
   Props: `warnings: Warning[]`
   Returns `null` when `warnings` is empty.
   Renders a callout box (light amber background `#fffbeb`, amber border `#fbbf24`, `borderRadius: 10`, `padding: 12`, `marginBottom: 16`) with one row per warning: the appropriate lucide icon (same as WarningBadge: `AlertTriangle`/amber, `XCircle`/red, `Info`/gray, `HelpCircle`/gray at 14px) + text from `getWarningText(warning)` at 12px, `#92400e` (same as Toast warning text). Uses `StyleSheet.create()` only.
   — *Extension of the warning toast visual pattern (ui-guidelines §12, established F13): same amber palette, same text style, but rendered as a static inline View rather than an animated overlay.*

2. **`client/components/__tests__/WarningCallout-test.tsx`**
   New test file — see Tests to Write.

### Supabase Query Shapes

**`useItemById`** (new hook in `api/items.ts`):
```ts
supabase
  .from('items')
  .select(`
    *,
    category:categories!default_category_id(name),
    item_store_preferences(
      store_id, status, comment,
      store:stores(id, name, color_code)
    )
  `)
  .eq('id', itemId)
  .single()
```

Returns `MasterItem`. Enabled only when `itemId` is non-null.

### Acceptance Criteria

- [ ] `WarningBadge.tsx` no longer defines its own `Warning` interface; it imports `Warning` and `getWarningText` from `@/api/items`
- [ ] `ListItem.warnings` is typed as `Warning[]` (from `api/items`) instead of the loose inline type
- [ ] Opening the **Add Detail modal** for a master item with a warning (e.g., item assigned to an avoided store) shows the warning callout below the modal title
- [ ] The warning callout in the Add Detail modal updates reactively when the user changes the store or qty selection
- [ ] No warning callout appears for one-off items in the Add Detail modal
- [ ] Opening the **List Edit modal** for a list item linked to a master item with a warning shows the warning callout below the modal title
- [ ] The warning callout in the List Edit modal updates reactively when the user changes the store or qty selection
- [ ] No warning callout appears for one-off list items (no master item link) in the List Edit modal
- [ ] After a quick-add (`onCommitAdd`) of an item with warnings where the matching warning type is `toast_and_badge` in the user's profile, a warning toast appears
- [ ] After an add via the Add Detail modal (`onSaveEdited`) with the same conditions, a warning toast appears
- [ ] No warning toast fires if the warning type preference is `badge_only` or `off`
- [ ] `non_preferred` warnings never trigger a toast (the `WarningPreferences` type intentionally excludes `toast_and_badge` for `non_preferred`)
- [ ] Warning toast fires even if the user already saw the warning inline in the Add Detail modal
