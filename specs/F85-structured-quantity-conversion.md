## Feature: Structured Quantity Data Conversion

### Context

F79 added three JSONB quantity columns (`list_items.quantity_parsed`, `items.default_qty_parsed`, `items.alternate_qtys_parsed`) and left them unpopulated — the migration comment explicitly says *"Populated at write time by a future spec."* F85 is that spec.

Scope expanded from the original GitHub issue via comment on #85: the explicit `plural` field (packages table schema + parser + UI) is bundled here because `formatQuantity` still depends on `getPlural`/`DEFAULT_VOCABULARY` — the vocabulary-injection problem can't be closed without it.

**F85 delivers:**
1. Explicit `plural TEXT` column on the `packages` DB table
2. `packagePlural` field threaded through vocabulary → parser → `QuantityFields` → JSONB storage
3. `formatQuantity` cleaned up to use `fields.packagePlural` (no more `DEFAULT_VOCABULARY` dependency)
4. `VocabularyManagement` UI gains a "Plural form" input for packages
5. `parseQuantityText()` utility exported from `quantityFormat.ts`
6. All three JSONB quantity columns populated at write time (SmartAddItem + Items screen)

Position in input chain: F44 → F79 → **F85** → F77/F83 → F78/F76.

### JSONB Structure Definition

All three columns store instances of `QuantityParsed`:

```typescript
export type QuantityParsed = {
  count: number | null;
  packageType: string | null;
  packagePlural: string | null;   // explicit plural form; null for non-package quantities
  sizeQty: number | null;
  sizeUnit: string | null;
  sizeDescriptive: string | null;
};
```

**Column semantics:**
- `NULL` at the column level = no structured quantity available (pre-F85 rows, or unparseable text). A `QuantityParsed` object where all five quantity fields are null should never be written — write column `NULL` instead.
- `alternate_qtys_parsed[i]` is index-aligned with `alternate_qtys[i]`. A null element in the array means that specific entry did not parse cleanly.

---

### Display Model

**Model: write-time normalization.** The `quantity` TEXT column is the authoritative display field. All UI rendering reads `quantity` directly — no display components are changed by this spec, and no parsed-first rendering logic is introduced.

**Write-time normalization rule:** When `quantity_parsed` is non-null, the corresponding `quantity` TEXT field **must** be set to `formatQuantity(quantity_parsed)` at write time — not the raw user input. This guarantees consistency: "2 Cans" and "2 cans" both normalize to "2 cans" because they produce identical `quantity_parsed`.

When `quantity_parsed` is null (one-off items, unparseable input), `quantity` stores the raw user text as-is.

This applies to all three write paths:
- `list_items.quantity` — `quantity_parsed != null ? formatQuantity(quantity_parsed) : rawText`
- `items.default_qty` — `default_qty_parsed != null ? formatQuantity(default_qty_parsed) : rawText`
- Each element of `items.alternate_qtys[i]` — `altParsed[i] != null ? formatQuantity(altParsed[i]) : rawText[i]`

**Inline edits (deferred):** When a user edits `quantity` inline on the list, `quantity` TEXT is updated as before and `quantity_parsed` is not re-parsed. This leaves them temporarily out of sync, but display is unaffected (reads `quantity` directly). F78 will re-parse the text column as fallback. This is intentionally deferred — see Deferred Items.

**This design is intentional and settled.** The `quantity` TEXT column is not a cache — it is the primary display value, normalized at write time to match the structured representation. A future spec could add parsed-first rendering at display sites, but that is a separate change not in scope here.

#### 3. Update `lookup()` private function

Add a check for `entry.plural`:

```typescript
function lookup(token: string, entries: VocabEntry[]): string | null {
  const normalized = token.toLowerCase();
  for (const entry of entries) {
    if (entry.canonical.toLowerCase() === normalized) return entry.canonical;
    if (entry.plural && entry.plural.toLowerCase() === normalized) return entry.canonical;
    for (const alias of entry.aliases) {
      if (alias.toLowerCase() === normalized) return entry.canonical;
    }
  }
  return null;
}
```

This means `lookupPackage('cans', vocabulary)` still returns `'can'` — existing callers are unaffected.

#### 4. Add `lookupPackageEntry`

```typescript
export interface PackageEntry {
  canonical: string;
  plural: string;
}

export function lookupPackageEntry(token: string, vocabulary: Vocabulary): PackageEntry | null {
  const normalized = token.toLowerCase();
  for (const entry of vocabulary.packages) {
    const pluralStr = entry.plural ?? `${entry.canonical}s`;
    const matches =
      entry.canonical.toLowerCase() === normalized ||
      pluralStr.toLowerCase() === normalized ||
      entry.aliases.some((a) => a.toLowerCase() === normalized);
    if (matches) return { canonical: entry.canonical, plural: pluralStr };
  }
  return null;
}
```

#### 5. Deprecate `getPlural`

Keep the function but add a `/** @deprecated Use packagePlural field from QuantityFields instead */` JSDoc comment. Do not delete it in this spec — it will be removed in a follow-up once all callers have been migrated.

#### 4. Export `parseQuantityText`

```typescript
export function parseQuantityText(text: string, vocabulary: Vocabulary): QuantityParsed | null {
  if (!text.trim()) return null;
  const candidate = assembleCandidate(groupTokens(classifyTokens(tokenize(text), vocabulary)));
  const result: QuantityParsed = {
    count: candidate.count,
    packageType: candidate.packageType,
    packagePlural: candidate.packagePlural,
    sizeQty: candidate.sizeQty,
    sizeUnit: candidate.sizeUnit,
    sizeDescriptive: candidate.sizeDescriptive,
  };
  if (result.count === null && result.packageType === null && result.sizeQty === null
      && result.sizeUnit === null && result.sizeDescriptive === null) {
    return null;
  }
  return result;
}
```

### Acceptance Criteria

- `packages` DB table has a `plural TEXT NOT NULL` column; seed data correctly maps `loaf→loaves`, `patty→patties`, `package→packages`, and `${canonical}s` for regular forms.
- Parser recognizes package plural forms (e.g. `"cans"`) via the new `plural` field without requiring them to be in `aliases`.
- `ParsedInput.packagePlural` is populated when a package token is resolved (e.g. `"2 cans"` → `packagePlural: 'cans'`).
- `formatQuantity({ count: 2, packageType: 'can', packagePlural: 'cans' })` returns `"2 cans"` without importing `DEFAULT_VOCABULARY`.
- `formatQuantity({ count: 2, packageType: 'loaf', packagePlural: 'loaves' })` returns `"2 loaves"`.
- `parseQuantityText("2 8oz cans", vocab)` returns `{ count: 2, packageType: 'can', packagePlural: 'cans', sizeQty: 8, sizeUnit: 'oz', sizeDescriptive: null }`.
- `parseQuantityText("")` and `parseQuantityText("random words")` return `null`.
- Adding an item via SmartAddItem quick-add stores a non-null `quantity_parsed` on `list_items` when the qty is parseable, and `quantity` is set to `formatQuantity(quantity_parsed)` (normalized form).
- When qty is unparseable (one-off), `quantity_parsed` is null and `quantity` stores the raw text unchanged.
- Adding via the one-off or edit-before-add path follows the same normalization rule.
- Creating or editing a master item in the Items screen stores `default_qty_parsed` and `alternate_qtys_parsed`, and `default_qty` / each `alternate_qtys` element is normalized to `formatQuantity(...)` when parsed.
- Undo of an Items screen edit restores the JSONB columns and the normalized text columns to their pre-edit values.
- `VocabularyManagement` shows a "Plural form" input when `type === 'packages'`; the field pre-fills with `${canonical}s` and can be overridden.
- Saving a new package vocabulary entry via VocabularyManagement stores the `plural` field.
