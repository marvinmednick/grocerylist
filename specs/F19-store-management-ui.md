## Feature: Store Management UI

### Context

Three issues were batched into F19:

- **#53** — Store editing UI: no way to rename or recolor an existing store after creation.
- **#54** — Store deletion UI: no way to delete stores; needs cascade warnings before confirming.
- **#62** — Store dropdown filter: the store preference dropdown inside the item edit modal renders all stores as a flat list; when there are many stores this is unwieldy.

**No separate design doc.** Decisions are recorded inline in this spec.

**Key files for context:**
- `components/StoreSelector.tsx` — active store dropdown in the shopping list header (create already implemented)
- `app/(tabs)/items.tsx` — item edit modal with store preference section (F16)
- `api/metadata.ts` — `useMetadata`, `useCreateStore`

---

### Design Decisions

**Where to surface edit/delete (#53, #54):** Each row in the `StoreSelector` dropdown gains a small pencil icon on the right. Tapping the store name selects it (unchanged). Tapping the pencil icon opens an **Edit Store modal** (pre-filled with current name + color). The edit modal follows the established dialog modal pattern (§7a of `docs/design/ui-guidelines.md`): `Trash2` delete icon in a red pill on the left of the header, title in center, X close on the right.

**Deletion confirmation (#54):** Instead of `Alert.alert`, the delete confirmation is shown inline within the edit modal. Tapping the `Trash2` icon reveals a confirmation section (below the color picker) that shows the cascade impact and two buttons — "Cancel delete" and "Delete" (red). This approach works identically on all platforms and allows displaying the cascade counts.

**Deletion cascade (#54):** The `stores` table has three FK references that matter:
- `item_store_preferences.store_id` — `ON DELETE CASCADE` (already in schema — preferences deleted automatically)
- `list_items.store_id` — `ON DELETE SET NULL` (already in schema — list items lose store assignment)
- `shopping_trips.primary_store_id` — currently no `ON DELETE` clause (defaults to RESTRICT); **must be changed to `ON DELETE SET NULL`** via a migration or deletion will fail when trips reference the store

A migration adds this FK change. Before showing the confirmation, the app fetches:
1. Count of `item_store_preferences` rows for the store being deleted (= item preferences that will be removed)
2. Count of active `list_items` (where `archived_at IS NULL`) with this `store_id` (= items that will lose their store assignment)

Trips are not blocked (FK is changed to SET NULL). No other hard blocks.

**Undo:**
- Store rename/recolor: register undo (data mutation, easily reversed)
- Store delete: **no undo** — cascade side-effects (preferences removed, items unassigned) are too broad to reliably reverse

**Active store fallback on delete (#54):** If the currently active store is deleted, `StoreSelector` calls `onStoreChange` with the first remaining store's ID. If no stores remain, `onStoreChange('')` to clear the active store. The parent (`index.tsx`) already handles an empty active store gracefully.

**Store dropdown filter threshold (#62):** 6 stores. When `stores.length > 6`, a `TextInput` appears at the top of the pref dropdown. Typing filters stores by case-insensitive substring match on the store name. The filter resets whenever the dropdown opens or closes. `autoFocus` is enabled on the filter input so the user can type immediately after the dropdown opens (only when `stores.length > 6`).

### Household Scoping

All store mutations already require `household_id` in `useCreateStore`. The new `useUpdateStore` and `useDeleteStore` mutations must include `.eq('household_id', householdId)` in their Supabase queries. No new tables involved.

#### 2. `client/api/metadata.ts`

Add three exports:

**`useUpdateStore`** — rename/recolor a store:
```typescript
export const useUpdateStore = () => {
  const queryClient = useQueryClient();
  const { householdId } = useHousehold();

  return useMutation({
    mutationFn: async ({ id, name, color_code }: { id: string; name: string; color_code: string }) => {
      if (!householdId) throw new Error('No household ID found');
      const { data, error } = await supabase
        .from('stores')
        .update({ name, color_code })
        .eq('id', id)
        .eq('household_id', householdId)
        .select()
        .single();
      if (error) throw error;
      return data;
    },
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ['metadata'] });
    },
  });
};
```

**`useDeleteStore`** — delete a store (cascades handled by DB):
```typescript
export const useDeleteStore = () => {
  const queryClient = useQueryClient();
  const { householdId } = useHousehold();

  return useMutation({
    mutationFn: async (storeId: string) => {
      if (!householdId) throw new Error('No household ID found');
      const { error } = await supabase
        .from('stores')
        .delete()
        .eq('id', storeId)
        .eq('household_id', householdId);
      if (error) throw error;
    },
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ['metadata'] });
      queryClient.invalidateQueries({ queryKey: ['shopping_list'] });
    },
  });
};
```

**`useStoreCascadeInfo`** — fetch cascade counts before confirming deletion:
```typescript
export const useStoreCascadeInfo = (storeId: string | null) => {
  return useQuery({
    queryKey: ['store-cascade', storeId],
    queryFn: async () => {
      if (!storeId) return { itemPrefsCount: 0, activeListItemsCount: 0 };
      const [prefsResult, listItemsResult] = await Promise.all([
        supabase
          .from('item_store_preferences')
          .select('id', { count: 'exact', head: true })
          .eq('store_id', storeId),
        supabase
          .from('list_items')
          .select('id', { count: 'exact', head: true })
          .eq('store_id', storeId)
          .is('archived_at', null),
      ]);
      if (prefsResult.error) throw prefsResult.error;
      if (listItemsResult.error) throw listItemsResult.error;
      return {
        itemPrefsCount: prefsResult.count ?? 0,
        activeListItemsCount: listItemsResult.count ?? 0,
      };
    },
    enabled: !!storeId,
    staleTime: 0,
  });
};
```

**New handlers:**
```typescript
const openEditModal = (store: { id: string; name: string; color_code: string }) => {
  setEditingStore(store);
  setEditStoreName(store.name);
  setEditStoreColor(store.color_code);
  setShowDeleteConfirm(false);
  setIsDropdownOpen(false);
  setIsEditModalOpen(true);
};

const closeEditModal = () => {
  setEditingStore(null);
  setEditStoreName('');
  setEditStoreColor(STORE_COLORS[0]);
  setShowDeleteConfirm(false);
  setIsEditModalOpen(false);
};

const handleUpdateStore = async () => {
  if (!editingStore || !editStoreName.trim()) return;
  const prev = { id: editingStore.id, name: editingStore.name, color_code: editingStore.color_code };
  const next = { id: editingStore.id, name: editStoreName.trim(), color_code: editStoreColor };
  await updateStoreMutation.mutateAsync(next);
  pushAction({
    label: `Renamed store to ${next.name}`,
    undo: async () => { await updateStoreMutation.mutateAsync(prev); },
    redo: async () => { await updateStoreMutation.mutateAsync(next); },
  });
  closeEditModal();
};

const handleDeleteStore = async () => {
  if (!editingStore) return;
  const deletedId = editingStore.id;
  await deleteStoreMutation.mutateAsync(deletedId);
  if (deletedId === activeStoreId) {
    const remaining = stores.filter((s) => s.id !== deletedId);
    onStoreChange(remaining.length > 0 ? remaining[0].id : '');
  }
  closeEditModal();
};
```
