## Feature: Per-Entry Store ID

### Context

`store_id` currently lives on `list_items` (the parent row), shared by all `list_item_quantities` entries under it. This is a design miss: each quantity entry should own its store assignment independently.

**Problem this creates today:** when F78's "Add New (same store)" adds a second entry under an existing parent, both entries share one `store_id`. Editing the store in the edit modal writes to the parent, moving both entries together — the user cannot change the store on just one.

**After this migration:** `store_id` lives on `list_item_quantities`. A single parent can have entries at different stores, each independently editable. The list groups rows by `entry.store_id`, not `parent.store_id`.

### Database / Schema Changes

#### Migration file: `supabase/migrations/20250101000020_f104_per_entry_store_id.sql`

```sql
BEGIN;

-- Add store_id to list_item_quantities
ALTER TABLE list_item_quantities
  ADD COLUMN store_id UUID REFERENCES stores(id) ON DELETE SET NULL;

CREATE INDEX list_item_quantities_store_idx ON list_item_quantities(store_id);

-- Copy store_id from parent list_items row into each entry
UPDATE list_item_quantities q
SET store_id = li.store_id
FROM list_items li
WHERE q.list_item_id = li.id
  AND li.store_id IS NOT NULL;

-- Null out list_items.store_id — column retained but deprecated (always NULL going forward)
UPDATE list_items SET store_id = NULL;

COMMIT;
```

**Note:** `list_items.store_id` column is kept in the schema (FK, RLS not affected) but its value is always `NULL` after this migration. A future migration may formally drop it. Do not write `store_id` to `list_items` in any new code.

#### `supabase/full_schema.sql`

Add `store_id UUID REFERENCES stores(id) ON DELETE SET NULL` to the `list_item_quantities` table definition (after `quantity_parsed`).

Add an inline comment on `list_items.store_id`:
```sql
store_id UUID REFERENCES stores(id) ON DELETE SET NULL, -- deprecated: always NULL as of F104; store lives on list_item_quantities
```

#### `useEndTrip`

```typescript
// Replace:

  return { trip, items: [] };

// With:

  .from('list_item_quantities')
  .update({ archived_at: new Date().toISOString(), trip_id: trip.id })
  .eq('is_purchased', true)
  .is('archived_at', null);

  entriesUpdate = entriesUpdate.eq('store_id', store_id);
```

### `flatData` Grouping Change (index.tsx)

#### Updated `FlatListItem` type

```typescript
type FlatListItem =
  | { type: 'header'; id: string; title: string; storeId: string; entries: Array<{ parent: ListItem; entry: QuantityEntry }> }
  | { type: 'item'; id: string; data: { parent: ListItem; entry: QuantityEntry } };
```

(`parents: ListItem[]` on header is replaced by `entries: Array<{ parent, entry }>`)

#### Updated grouping logic

```typescript
const flatData = useMemo(() => {
  if (!listItems) return [];
  const groups: Record<string, { name: string; colorCode: string | null; entries: Array<{ parent: ListItem; entry: QuantityEntry }> }> = {};
  listItems.forEach((parent) => {
    parent.quantities.forEach((entry) => {
      const storeKey = entry.store_id || 'other';
      const storeName = entry.store?.name || 'Other';
      if (!groups[storeKey]) groups[storeKey] = { name: storeName, colorCode: entry.store?.color_code ?? null, entries: [] };
      groups[storeKey].entries.push({ parent, entry });
    });
  });
  const result: FlatListItem[] = [];
  Object.entries(groups).forEach(([storeKey, { name, entries }]) => {
    result.push({ type: 'header', id: `header-${storeKey}`, title: name, storeId: storeKey, entries });
    entries.forEach(({ parent, entry }) => {
      result.push({ type: 'item', id: entry.id, data: { parent, entry } });
    });
  });
  return result;
}, [listItems]);
```

#### `hasPurchased` check in `renderItem`

```typescript
// Old:
```

#### `handleSaveEdit`

Store is no longer a "parent" field. Restructure into parent-only and entry-level change detection:

```typescript
const parentSnapshot = { name: editingParent.name, category_id: editingParent.category_id };
const parentUpdates  = { name: editName, category_id: editingParent.category_id };

const entrySnapshot  = { quantity: editingEntry.quantity, store_id: editingEntry.store_id };
const entryUpdates   = { quantity: editQty || null, store_id: editStoreId || null };

const parentChanged = parentSnapshot.name !== parentUpdates.name;
const entryChanged  = entrySnapshot.quantity !== entryUpdates.quantity
                   || entrySnapshot.store_id  !== entryUpdates.store_id;

if (!parentChanged && !entryChanged) { /* close */ return; }

if (parentChanged) {
  await updateListItemFields({ id: editingParent.id, name: editName });
}
if (entryChanged) {
  await updateQuantityEntry({ id: editingEntry.id, ...entryUpdates });
}

pushAction({
  label: `Edited ${editingParent.name}`,
  undo: async () => {
    if (parentChanged) await updateListItemFields({ id: editingParent.id, ...parentSnapshot });
    if (entryChanged)  await updateQuantityEntry({ id: editingEntry.id, ...entrySnapshot });
  },
  redo: async () => {
    if (parentChanged) await updateListItemFields({ id: editingParent.id, ...parentUpdates });
    if (entryChanged)  await updateQuantityEntry({ id: editingEntry.id, ...entryUpdates });
  },
});
```

### Drag-to-Reorder Change (index.tsx `onDragEnd`)

Compare and update `entry.store_id` instead of `parent.store_id`:

```typescript
const draggedEntry  = draggedItem.data.entry;
const draggedParent = draggedItem.data.parent;
if (newStoreId && newStoreId !== (draggedEntry.store_id ?? 'other')) {
  const originalStoreId = draggedEntry.store_id;

  const itemName = draggedParent.name;
  await updateQuantityEntry({ id: entryId, store_id: newStoreId === 'other' ? null : newStoreId });

    label: `Moved ${itemName} to ${newStoreName}`,
    undo: async () => { await updateQuantityEntry({ id: entryId, store_id: originalStoreId }); },
    redo: async () => { await updateQuantityEntry({ id: entryId, store_id: newStoreId === 'other' ? null : newStoreId }); },
  });
}
```

### Undo/Redo Registration

All undo/redo closures that previously used `store_id` from `parent` must now read it from `entry`. Specifically:

| Action | Old source | New source |
|--------|-----------|-----------|
| Edit store (handleSaveEdit) | `editingParent.store_id` | `editingEntry.store_id` |
| Drag to reorder (onDragEnd) | `draggedParent.store_id` | `draggedEntry.store_id` |
| Combine store move (handleDuplicateCombine) | `duplicateMatch.store_id` | `targetEntry.store_id` |
| Delete undo (handleDelete) | `parentToDelete.store_id` | `entryToDelete.store_id` |

All undo/redo calls that previously called `updateListItemFields({ store_id })` must be changed to `updateQuantityEntry({ id: entry.id, store_id })`.

### Acceptance Criteria

- [ ] Adding an item to the list stores `store_id` on the quantity entry, not the parent. The parent's `store_id` remains `null`.
- [ ] Adding a second entry under the same parent (via F78 Add New same-store) stores that entry's `store_id` independently.
- [ ] The shopping list groups rows by `entry.store_id`; entries for the same item at different stores appear in separate store sections.
- [ ] Opening the edit modal for an entry shows that entry's store in the dropdown (not the parent's).
- [ ] Saving a store change in the edit modal updates `list_item_quantities.store_id` for that entry only; sibling entries are unaffected.
- [ ] Dragging a row to a different store section updates that entry's `store_id` with undo/redo.
- [ ] End Trip at a specific store archives only entries whose `entry.store_id` matches; entries at other stores are untouched.
- [ ] F78 Combine store move (active-different-store) updates the active entry's `store_id`, not the parent's.
- [ ] F78 classifyDuplicateState returns `active-same-store` / `active-different-store` based on the active entry's `store_id`.
- [ ] Trip history items display the store from the archived entry's `store_id`.
- [ ] All 629 existing tests pass.
