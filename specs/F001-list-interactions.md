## Context

Addresses three related UX problems documented in `docs/design/list-interactions.md`:
1. Two redundant headers (Expo tab header + custom `globalHeader`)
2. The info-circle icon is misleading — it navigates to a full-screen modal just for sign-out
3. Tap targets are optimized for list-building (tap name = edit), not for active shopping (tap anywhere = check off)

The result is a single consolidated header with a mode toggle (Shopping/Planning), undo/redo, and a user avatar that opens an inline menu.

## New Files

**`client/components/UserAvatar.tsx`**
- Reads `displayName`, `displayNameShort`, `avatarColor` from `useHousehold()`
- Renders a colored circle (default color `#2563eb` if `avatarColor` is null) with the first letter of `displayNameShort`, falling back to first letter of `displayName`, falling back to `?`
- On press: toggles a local `menuVisible` boolean
- Menu implementation: an absolutely-positioned `View` layered over the screen using a transparent full-screen `Pressable` backdrop (dismiss on outside tap) — no new dependencies
- Menu contains: display name at top (non-interactive), and a Sign Out row
- Sign Out calls `supabase.auth.signOut()`, then `queryClient.clear()`, then `router.replace('/auth')` — same logic currently in `modal.tsx`

## Database / Schema Changes

The `profiles` table is missing `display_name_short` and `color` columns. A migration is required:

```sql
-- supabase/migrations/[timestamp]_add_profile_display_fields.sql
ALTER TABLE profiles
  ADD COLUMN IF NOT EXISTS display_name_short TEXT,
  ADD COLUMN IF NOT EXISTS color TEXT DEFAULT '#2563eb';
```

Existing profiles will have `null` for `display_name_short` and `#2563eb` for `color`. The `UserAvatar` component must handle `null` gracefully (see fallback logic above).

## Supabase Query Shapes

Extend the existing query in `lib/household.tsx`:

```typescript
const { data, error } = await supabase
  .from('profiles')
  .select('household_id, display_name, display_name_short, color')
  .eq('id', session.user.id)
  .single();
```

No join syntax needed — single table, no FK ambiguity.

The avatar menu uses a `Pressable` backdrop for dismissal. `onLongPress` for the edit modal (shopping mode) uses React Native's `Pressable`, which works on web via mousedown/mouseup timing. No `Alert.alert` changes are introduced. The existing `Alert.alert` in `handleEndTrip` is unchanged.

## Acceptance Criteria

- Only one header is visible on the shopping list screen (the custom header; the Expo tab header is gone)
- Header shows: title "Shopping List", mode toggle icon, undo button with badge, redo button with badge, user avatar circle
- Avatar circle shows the correct first letter with a colored background
- Tapping the avatar opens an inline dropdown (not a new screen) with the user's display name and a Sign Out option
- Tapping Sign Out signs out, clears the cache, and navigates to `/auth`
- Tapping outside the avatar menu closes it without action
- Default mode on launch is Shopping mode (cart icon active)
- **Shopping mode**: single tap anywhere on an item row (not the grip handle) toggles purchased
- **Shopping mode**: long press on an item row (not the grip handle) opens the edit modal
- **Shopping mode**: a small pencil edit icon is visible at the trailing edge of each item row
- **Planning mode**: tapping the checkbox toggles purchased; tapping the item name opens the edit modal (current behavior)
- **Planning mode**: no pencil edit icon visible
- Mode toggle button switches between modes and its icon changes (cart ↔ pencil)
- Drag-and-drop reordering (long press on grip handle) works identically in both modes
