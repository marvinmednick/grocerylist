## Feature: Duplicate Entry Handling

### Context

When a user adds an item that already exists on the active shopping list, the app should detect the duplicate and present a resolution dialog instead of silently creating a second row. The user can combine quantities (sum or multi-pack), keep the addition as a separate quantity entry under the same logical item, enter a custom quantity, or cancel. Cross-store and already-purchased scenarios have tailored action sets.

This feature also adds a passive "on list" indicator to SmartAddItem dropdown rows so the user sees at a glance which candidates are already on the list.

Design decisions recorded in `docs/design/F78-duplicate-entry-handling.md`. Read it before starting — it covers the rationale for every UI and data decision.

### Combine Computation Algorithm

Add to `lib/quantityFormat.ts`. The function `combineQuantities` takes two `QuantityParsed` values and returns structured options:

```typescript
export interface CombineOption {
  label: string;          // display text for button, e.g. "3 lb" or "2 × 1.5 lb"
  type: 'sum' | 'multipack';
  result: QuantityParsed; // the combined quantity value
}

export interface CombineOptions {
  options: CombineOption[];
}
```

**Logic (in priority order):**

1. **One or both empty** (all fields null): use the non-empty value as-is. Return a single sum option with the non-empty value.

2. **Pure counts** (both have `count` only, no package/size/descriptive): sum the counts. Return `[{ type: 'sum', result: { count: a.count + b.count, ... nulls } }]`.

3. **Same unit, no package** (both have `sizeQty` + `sizeUnit`, same `sizeUnit`, no `packageType`):
   - **Sum**: add `sizeQty` values → e.g., "3 lb"
   - **Multi-pack** (only when both `sizeQty` are equal): `count = 2, sizeQty = original, sizeUnit = original` → e.g., "2 × 1.5 lb"
   - If `sizeQty` values differ, offer sum only (no multi-pack).

4. **Same package type** (both have `packageType`, same `packageType`):
   - Sum: add `count` values (treating null as 1) → e.g., "3 boxes"
   - Multi-pack: only when both have identical `sizeQty` + `sizeUnit` + `count`.

5. **Incompatible** (different units, different package types, convertible-but-different like lb/oz): return `null`. The dialog will show Add New / Custom / Cancel only.

The `formatCombineOption` function uses the existing `formatQuantity` for the sum case. For multi-pack, format as `"{count} × {sizeQty}{sizeUnit}"` (e.g., "2 × 1.5 lb").

### Duplicate Detection Flow

**Entry points** — all five add paths in SmartAddItem must route through duplicate detection:

1. `onCommitAdd` (tap item name in dropdown)
2. `onOneOffAdd` (tap one-off "Add" button)
3. `onAcceptTop` (Enter key / voice quick-accept)
4. `onSaveEdited` (Save in edit-before-add modal)
5. `onOneOffEditAdd` (Add in one-off edit modal)

**Pattern — wrap each path:**

```typescript
// Before: direct add
const onCommitAdd = async (...) => {
  const result = await forwardAction();
  pushAction(...);
  clearAndClose();
};

// After: check for duplicate first
const onCommitAdd = async (...) => {
  const match = findDuplicate(item.id, item.name, listItems);
  if (match) {
    // Save pending add details + current query, show dialog
    setSavedQuery(query);
    setPendingAdd({ itemId: item.id, name: item.name, quantity: selection.qty, quantityParsed, storeId: selection.storeId, categoryId: item.default_category_id, warnings, matchMetadata: aliasMatchMetadata(interpretation), forwardAction });
    setDuplicateMatch(match);
    return; // don't execute the add yet
  }
  // No duplicate — proceed as before
  const result = await forwardAction();
  pushAction(...);
  clearAndClose();
};
```

**PendingAdd type:**

```typescript
interface PendingAddDetails {
  itemId: string | null;
  name: string;
  quantity: string;
  quantityParsed: QuantityParsed | null;
  storeId: string | null;
  categoryId: string | null;
  warnings: Warning[];
  matchMetadata?: AliasMatchMetadata;
  forwardAction: () => Promise<{ parent: any; entry: any }>;
}
```

### Dialog Action Handlers

Each action is handled by a callback passed to `DuplicateResolutionDialog`. All handlers live in SmartAddItem (they need access to mutations, undo, etc.).

#### Combine (sum or multi-pack)

```typescript
const handleCombine = async (option: CombineOption) => {
  const match = duplicateMatch!;
  const targetEntry = match.quantities.find(e => !e.is_purchased && !e.archived_at)!;
  const previousQty = targetEntry.quantity;
  const previousQtyParsed = targetEntry.quantity_parsed;

  await updateQuantityEntry({
    id: targetEntry.id,
    quantity: formatQuantity(option.result),
    quantity_parsed: option.result,
  });

  pushAction({
    label: `Combined ${match.name}`,
    undo: async () => {
      await updateQuantityEntry({
        id: targetEntry.id,
        quantity: previousQty,
        quantity_parsed: previousQtyParsed,
      });
    },
    redo: async () => {
      await updateQuantityEntry({
        id: targetEntry.id,
        quantity: formatQuantity(option.result),
        quantity_parsed: option.result,
      });
    },
  });

  dismissDialog();
  clearAndClose();
};
```

#### Add New (append quantity entry)

```typescript
const handleAddNew = async () => {
  const match = duplicateMatch!;
  const pending = pendingAdd!;

  const result = await addQuantityEntry({
    listItemId: match.id,
    quantity: pending.quantity,
    quantityParsed: pending.quantityParsed,
  });

  const tracker = { currentEntryId: result.id };

  pushAction({
    label: `Added ${match.name} (${pending.quantity})`,
    undo: async () => {
      await deleteItem(tracker.currentEntryId);
    },
    redo: async () => {
      const redone = await addQuantityEntry({
        listItemId: match.id,
        quantity: pending.quantity,
        quantityParsed: pending.quantityParsed,
      });
      tracker.currentEntryId = redone.id;
    },
  });

  dismissDialog();
  clearAndClose();
};
```

#### Custom

```typescript
const handleCustom = async (customQty: string) => {
  const match = duplicateMatch!;
  const targetEntry = match.quantities.find(e => !e.is_purchased && !e.archived_at)!;
  const previousQty = targetEntry.quantity;
  const previousQtyParsed = targetEntry.quantity_parsed;

  const parsedCustom = parseQuantityText(customQty, vocab);
  const normalizedQty = normalizeQuantityText(customQty, parsedCustom);

  await updateQuantityEntry({
    id: targetEntry.id,
    quantity: normalizedQty,
    quantity_parsed: parsedCustom,
  });

  pushAction({
    label: `Updated ${match.name}`,
    undo: async () => {
      await updateQuantityEntry({
        id: targetEntry.id,
        quantity: previousQty,
        quantity_parsed: previousQtyParsed,
      });
    },
    redo: async () => {
      await updateQuantityEntry({
        id: targetEntry.id,
        quantity: normalizedQty,
        quantity_parsed: parsedCustom,
      });
    },
  });

  dismissDialog();
  clearAndClose();
};
```

#### Cross-Store Combine at Target Store (move + combine)

When the user picks "Combine at Store B" (the incoming store):

```typescript
const handleCrossStoreCombine = async (option: CombineOption, targetStoreId: string) => {
  const match = duplicateMatch!;
  const targetEntry = match.quantities.find(e => !e.is_purchased && !e.archived_at)!;
  const previousQty = targetEntry.quantity;
  const previousQtyParsed = targetEntry.quantity_parsed;
  const previousStoreId = match.store_id;

  // Update store on parent + quantity on entry
  await updateListItemFields({ id: match.id, store_id: targetStoreId });
  await updateQuantityEntry({
    id: targetEntry.id,
    quantity: formatQuantity(option.result),
    quantity_parsed: option.result,
  });

  pushAction({
    label: `Combined ${match.name}`,
    undo: async () => {
      await updateListItemFields({ id: match.id, store_id: previousStoreId });
      await updateQuantityEntry({
        id: targetEntry.id,
        quantity: previousQty,
        quantity_parsed: previousQtyParsed,
      });
    },
    redo: async () => {
      await updateListItemFields({ id: match.id, store_id: targetStoreId });
      await updateQuantityEntry({
        id: targetEntry.id,
        quantity: formatQuantity(option.result),
        quantity_parsed: option.result,
      });
    },
  });

  dismissDialog();
  clearAndClose();
};
```

### Cross-Store Add New — Special Case

When Add New is chosen in a cross-store scenario, the incoming item needs a **new** `list_items` parent row at the new store (not an entry under the existing parent, which is at a different store). Use the existing `useAddToList` mutation (creates parent + entry), not `useAddQuantityEntry`.

```typescript
const handleCrossStoreAddNew = async () => {
  const pending = pendingAdd!;
  const result = await addItem(pending); // uses useAddToList — creates new parent at incoming store
  const tracker = { currentId: result.parent.id };

  pushAction({
    label: `Added ${pending.name}`,
    undo: async () => { await deleteItem(tracker.currentId); },
    redo: async () => {
      const redone = await addItem(pending);
      tracker.currentId = redone.parent.id;
    },
  });

  dismissDialog();
  clearAndClose();
};
```

### Undo/Redo Registration

| Action | Label | Undo | Redo |
|--------|-------|------|------|
| Combine (sum/multi-pack) | `Combined {name}` | Restore previous qty + qty_parsed on the edited entry | Re-apply the combined qty |
| Custom | `Updated {name}` | Restore previous qty + qty_parsed on the edited entry | Re-apply custom qty |
| Add New (same store) | `Added {name} ({qty})` | Delete the appended quantity entry (via `useDeleteListItem`) | Re-insert entry (mutable tracker for new ID) |
| Cross-store combine at A | `Combined {name}` | Restore previous qty on entry | Re-apply combined qty |
| Cross-store combine at B | `Combined {name}` | Restore previous store_id on parent + previous qty on entry | Re-apply store move + combined qty |
| Cross-store Add New | `Added {name}` | Delete the new parent (via `useDeleteListItem`) | Re-insert (mutable tracker) |
| Cancel | — | No undo | — |

### Passive "on list" Indicator

In SmartAddItem dropdown result rows, add after the orphan tokens in `resultTitleRow`:

```tsx
<View style={styles.resultTitleRow}>
  <Text style={styles.resultName}>{interpretation.name}</Text>
  {interpretation.orphans.length > 0 ? (
    <Text style={styles.orphanText}>{interpretation.orphans.join(' ')}</Text>
  ) : null}
  {isOnList(interpretation.matchedItemId) && (
    <Text style={styles.onListIndicator}>on list</Text>
  )}
</View>
```

The `isOnList` function checks whether the item ID exists in the `listItems` prop:

```typescript
const onListItemIds = useMemo(() => {
  const ids = new Set<string>();
  for (const item of listItems) {
    if (item.item_id) ids.add(item.item_id);
  }
  return ids;
}, [listItems]);

const isOnList = (itemId: string | null | undefined): boolean => {
  return !!itemId && onListItemIds.has(itemId);
};
```

For one-off items in the dropdown, skip the indicator (one-offs match by name, and the dropdown one-off row is always the raw input — detection happens at add time).

### Acceptance Criteria

- [ ] Adding an item that already exists (same `item_id`) on the active list shows the duplicate resolution dialog instead of creating a second row
- [ ] Adding a one-off item whose name (case-insensitive, trimmed) matches an existing one-off shows the dialog
- [ ] Dialog shows correct summary line: "You already have {qty} at {store}"
- [ ] Same-store duplicate offers Combine (sum), Combine (multi-pack when applicable), Add New, Custom, and Cancel
- [ ] Cross-store duplicate offers per-store Combine options (one per line), Add New, Custom, and Cancel
- [ ] Purchased item duplicate shows informational summary and offers Add New, Custom, and Cancel only (no Combine)
- [ ] Combine (sum) correctly updates the existing quantity entry with the summed value
- [ ] Combine (multi-pack) correctly updates the existing quantity entry with the multi-pack format
- [ ] Add New appends a new `list_item_quantities` row under the same `list_items` parent (same-store)
- [ ] Cross-store Add New creates a new `list_items` parent at the incoming store
- [ ] Custom replaces the Combine section with inline text input; Cancel returns to main dialog view; ✕ dismisses entirely
- [ ] Custom Confirm updates the existing quantity entry with the user-entered value
- [ ] Cancel / ✕ restores the SmartAddItem search query to what the user had typed
- [ ] Every dialog action (Combine, Add New, Custom) registers a correct undo action
- [ ] Undo after Combine restores the previous quantity value
- [ ] Undo after Add New removes the appended quantity entry
- [ ] Undo after cross-store combine at B restores both the previous store and quantity
- [ ] SmartAddItem dropdown rows show "on list" label (muted gray) for items already on the active list
- [ ] "on list" indicator appears regardless of purchased/active state
- [ ] Duplicate detection fires for all add paths: manual tap, one-off, Enter/voice quick-accept, edit-before-add Save
- [ ] Dialog is bottom-anchored (card slides up from bottom, list content visible above)
- [ ] Button styling is uniform (gray-100 background, dark text) with Cancel as text-only
