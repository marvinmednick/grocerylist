## Feature: List Display Density & Warnings

### Context

Redesign the shopping list item row for better phone screen density using a multi-line layout. Add a `short_name` field to master items for compact display. Implement a warning badge and toast system that reads warning data from `list_items.warnings` (populated by F12 at add time). Add warning presentation preferences to Settings.

Design decisions recorded in `docs/design/F13-list-display-warnings.md`.

**Important:** F13 builds the **display infrastructure** — row layout, badge rendering, toast variant, settings UI. F12 (Smart Entry Model, implemented after F13) will populate `list_items.warnings` at add time and create the `item_store_preferences` table. Until F12 ships, warnings will be empty and badges won't appear. The `short_name` field and multi-line row layout are fully functional in F13.

### Database / Schema Changes

**Migration file:** `supabase/migrations/20250101000010_f13_display_warnings.sql`

```sql
-- F13: List Display Density & Warnings

-- 1. Add short_name to items (nullable, user-defined display name)
ALTER TABLE items ADD COLUMN IF NOT EXISTS short_name TEXT;

-- 2. Add warnings JSONB to list_items (populated by F12 at add time)
ALTER TABLE list_items ADD COLUMN IF NOT EXISTS warnings JSONB DEFAULT '[]';

-- 3. Add warning_preferences JSONB to profiles (per-user display prefs)
ALTER TABLE profiles ADD COLUMN IF NOT EXISTS warning_preferences JSONB DEFAULT '{
  "avoided": "toast_and_badge",
  "unavailable": "toast_and_badge",
  "non_preferred": "badge_only",
  "non_standard_qty": "badge_only"
}';
```

**Also update `supabase/full_schema.sql`** to include the three new columns in the respective CREATE TABLE statements (for reference/new deployments).

### Supabase Query Shapes

**Shopping list query (updated in `useShoppingList`):**

The existing select in `api/list.ts` needs to add `warnings` and pull `short_name` from the joined master item:

```typescript
.select(`
  *,
  store:stores!store_id(name, color_code),
  category:categories!category_id(name, sort_order),
  master_item:items!item_id(short_name)

```

The `warnings` column is included in `*` automatically. The `master_item.short_name` join provides the short name when the list item is linked to a master item.

### Detailed Implementation

#### 1. Multi-Line Item Row (`index.tsx`)

Replace the current single-line row layout with a two-line layout. Both `shopping` and `planning` mode renderItem branches need updating.

**Current row structure (line 358-387 for shopping mode):**
```
[Checkbox 24px] [Name - Qty (flex 1)] [Category 80px] [Pencil 24px] [Drag]
Fixed height: 48px
```

**New row structure:**
```
[Checkbox 24px] [Line 1: display name (flex 1)] [WarningBadge] [Drag]
                [Line 2: qty · category · store (flex 1)]
Auto height (no fixed height)
```

**Display name logic:** `listItem.master_item?.short_name || listItem.name`

**Line 2 content:** Dot-separated metadata string built from available fields:
```typescript
const secondaryParts = [
  listItem.quantity,
  listItem.category?.name,
  listItem.store?.name,
].filter(Boolean);
const secondaryText = secondaryParts.join(' · ');
```

**Style changes:**
- Remove `height: 48` from `itemRow` — use `minHeight: 48` and `paddingVertical: 6` instead
- Remove `colCategory` and `colEditIcon` styles (no longer separate columns)
- Add `nameText` style: `fontSize: 15, fontWeight: '500', color: '#111827'`
- Add `secondaryText` style: `fontSize: 12, color: '#6b7280', marginTop: 2`
- The text content area is a vertical `View` with `flex: 1`:
  ```tsx
  <View style={styles.textContent}>
    <Text style={[styles.nameText, listItem.is_purchased && styles.strikethrough]} numberOfLines={1}>
      {listItem.master_item?.short_name || listItem.name}
    </Text>
    {secondaryText ? (
      <Text style={styles.secondaryText} numberOfLines={1}>{secondaryText}</Text>
    ) : null}
  </View>
  ```

**Planning mode:** Same two-line layout. The tap target for editing is on the text content area (already works via `onPress={() => openEditModal(listItem)}`). Remove the separate pencil icon column.

**Shopping mode:** Same two-line layout. Long-press on text area opens edit modal (already exists). Remove the separate pencil icon.

#### 2. Warning Badge Component (`components/WarningBadge.tsx`)

A new component that renders warning icons and handles tap-to-popover.

```typescript
interface Warning {
  type: 'avoided' | 'unavailable' | 'non_preferred' | 'non_standard_qty';
  store_id?: string;
  store_name?: string;  // denormalized by F12 at add time; fallback to store_id
  comment?: string | null;
  preferred_stores?: string[];
  entered?: string;
  standard?: string[];
}

interface WarningBadgeProps {
  warnings: Warning[];
}
```

**Icon mapping** (from `docs/design/ui-guidelines.md` §2 Semantic Colors and design doc):

| `type` | Icon (lucide) | Color hex |
|--------|---------------|-----------|
| `avoided` | `AlertTriangle` | `#f59e0b` |
| `unavailable` | `XCircle` | `#ef4444` |
| `non_preferred` | `Info` | `#6b7280` |
| `non_standard_qty` | `HelpCircle` | `#6b7280` |

All icons are 14px.

**Rendering:** If `warnings` is empty or undefined, render nothing. Otherwise render a horizontal row of icons (one per warning).

**Tap → Popover:** Tapping any badge icon shows an absolutely-positioned tooltip near the badge. The popover shows a detail string for each warning:
- `avoided`: `"Avoided at {store_name} — {comment}"` (or without comment if null). Use `warning.store_name || warning.store_id || 'a store'` for the store name.
- `unavailable`: `"Unavailable at {store_name}"`. Same store name fallback.
- `non_preferred`: `"Preferred at: {preferred_stores.join(', ')}"`
- `non_standard_qty`: `"Qty {entered} is non-standard (usual: {standard.join(', ')})"`

**Popover dismissal:** Use a full-screen transparent `Pressable` overlay behind the popover. Tap anywhere outside dismisses.

**Popover style:**
```typescript
popover: {
  position: 'absolute',
  right: 0,
  top: '100%',  // below the badge
  backgroundColor: '#ffffff',
  borderRadius: 8,
  padding: 12,
  shadowColor: '#000',
  shadowOffset: { width: 0, height: 2 },
  shadowOpacity: 0.15,
  shadowRadius: 4,
  elevation: 4,
  minWidth: 200,
  maxWidth: 280,
  zIndex: 1000,
}
```

**Integration in `index.tsx`:** Place `<WarningBadge warnings={listItem.warnings} />` between the text content and the drag handle:
```tsx
<View style={styles.textContent}>
  {/* name + secondary */}
</View>
{listItem.warnings?.length > 0 && (
  <WarningBadge warnings={listItem.warnings} />
)}
<TouchableOpacity onLongPress={drag} ...>
  <GripVertical ... />
</TouchableOpacity>
```

#### 3. Toast Warning Variant (`components/Toast.tsx`)

Add an optional `variant` prop:

```typescript
interface ToastProps {
  message: string;
  visible: boolean;
  onDismiss: () => void;
  duration?: number;
  variant?: 'default' | 'warning';  // NEW
}
```

When `variant === 'warning'`:
- Background color: `#fffbeb` (amber-50 tint)
- Text color: `#92400e` (amber-800)
- Border: `1px solid #fbbf24` (amber-400)
- Duration default: `4000` (instead of `3000`)

Implementation: Apply conditional styles in the component based on `variant`:
```typescript
const containerStyle = variant === 'warning' ? styles.warningContainer : styles.container;
const textStyle = variant === 'warning' ? styles.warningText : styles.text;
const effectiveDuration = duration ?? (variant === 'warning' ? 4000 : 3000);
```

#### 4. Warning Preferences in Settings (`components/Settings.tsx`)

Add a new "Warnings" section after the existing "App" section.

**Warning preferences type:**
```typescript
export interface WarningPreferences {
  avoided: 'toast_and_badge' | 'badge_only' | 'off';
  unavailable: 'toast_and_badge' | 'badge_only' | 'off';
  non_preferred: 'badge_only' | 'off';
  non_standard_qty: 'toast_and_badge' | 'badge_only' | 'off';
}
```

**Default values** (matching the DB default):
```typescript
const DEFAULT_WARNING_PREFS: WarningPreferences = {
  avoided: 'toast_and_badge',
  unavailable: 'toast_and_badge',
  non_preferred: 'badge_only',
  non_standard_qty: 'badge_only',
};
```

**UI for each warning type:** A row with the warning type label on the left and a segmented control on the right.

**Segmented control:** Three horizontally adjacent buttons (`Toast+Badge | Badge | Off`), or two for `non_preferred` (`Badge | Off`). Selected segment gets `backgroundColor: '#2563eb'` with white text; unselected gets `backgroundColor: '#f3f4f6'` with `#374151` text.

**Segmented control labels:**
| Value | Label |
|-------|-------|
| `toast_and_badge` | `Toast + Badge` |
| `badge_only` | `Badge` |
| `off` | `Off` |

**Warning type labels:**
| Key | Display Label |
|-----|---------------|
| `avoided` | `Store Avoidance` |
| `unavailable` | `Store Unavailable` |
| `non_preferred` | `Non-Preferred Store` |
| `non_standard_qty` | `Non-Standard Qty` |

**Data flow:**
1. Read `warning_preferences` from the household/profile hook (new field added to profile query)
2. Local state initialized from the profile value (or defaults if null)
3. Changes saved with the existing "Save Changes" button (bundle with other profile updates)
4. Pass `warning_preferences` in the `useUpdateProfile` mutation payload
