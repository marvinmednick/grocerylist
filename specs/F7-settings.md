## Feature: Settings Screen

### Context

Adds a Settings modal accessible from the UserAvatar dropdown, allowing users to edit their profile (display name, short name, color) and toggle dark mode (preference stored; visual theme deferred to F10). Also extends the shared header actions — undo, redo, and UserAvatar — to the Items and History tabs, which currently lack them.

Design decisions recorded in `docs/design/F7-settings.md`.

User scenarios addressed: Scenario 13 (sign out path unchanged), plus new profile customization and dark mode preference.

**`api/profile.ts`**

Three hooks:

```typescript
// Mutation: update own profile
export const useUpdateProfile = () => {
  const queryClient = useQueryClient();
  return useMutation({
    mutationFn: async ({ display_name, display_name_short, color }: {
      display_name: string;
      display_name_short: string;
      color: string;
    }) => {
      const { data: { session } } = await supabase.auth.getSession();
      if (!session) throw new Error('Not authenticated');
      const { error } = await supabase
        .from('profiles')
        .update({ display_name, display_name_short, color })
        .eq('id', session.user.id);
      if (error) throw error;
    },
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ['my_profile'] });
    },
  });
};

// Query: fetch household name
export const useHouseholdName = (householdId: string | null) => {
  return useQuery({
    queryKey: ['household_name', householdId],
    queryFn: async () => {
      const { data, error } = await supabase
        .from('households')
        .select('name')
        .eq('id', householdId!)
        .single();
      if (error) throw error;
      return data.name as string;
    },
    enabled: !!householdId,
  });
};

// Query: fetch colors of other household members (for conflict warning)
export const useHouseholdMemberColors = (householdId: string | null) => {
  return useQuery({
    queryKey: ['household_member_colors', householdId],
    queryFn: async () => {
      const { data: { session } } = await supabase.auth.getSession();
      if (!session || !householdId) return [];
      const { data, error } = await supabase
        .from('profiles')
        .select('color')
        .eq('household_id', householdId)
        .neq('id', session.user.id);
      if (error) throw error;
      return (data ?? []).map(p => p.color).filter(Boolean) as string[];
    },
    enabled: !!householdId,
  });
};
```

**`lib/theme.tsx`**

AsyncStorage-backed theme context. AsyncStorage key: `'@app_theme'`. Values: `'dark'` | `'light'` | unset (defaults to system colorScheme → treat as `false`/light).

```typescript
interface AppThemeContextType {
  isDark: boolean;
  toggleTheme: () => void;
}
```

- `AppThemeProvider` reads `AsyncStorage.getItem('@app_theme')` on mount and sets `isDark` accordingly (fall back to `false` if null/unset).
- `toggleTheme` flips `isDark` and writes the new value to `AsyncStorage.setItem('@app_theme', newValue)`.
- `useAppTheme()` returns the context; throws if used outside provider.

### Undo/Redo Registration

None. Profile settings changes are not undoable. Do not call `pushAction` for any mutation in this feature.

---

### Household Scoping

- `useUpdateProfile` — **no household guard**. Updates the user's own `profiles` row using `session.user.id`. This is a self-update, not a household-scoped insert. No `household_id` in the update payload.
- `useHouseholdName` and `useHouseholdMemberColors` — read-only; no guard needed. Both use `enabled: !!householdId` to skip when household is not yet loaded.

---

### Realtime Mutation Tracking

Not applicable. No `list_items` writes in this feature. Do not use `incrementLocalMutation` / `decrementLocalMutation`.

---

### Platform Considerations

None. No `Alert.alert` calls. The Settings modal uses a standard form — no destructive confirmation dialogs needed.

### Acceptance Criteria

- Tapping the UserAvatar shows the dropdown with "Settings" above "Sign Out"
- Tapping "Settings" closes the dropdown and opens the Settings modal (slide up)
- Settings modal displays: Display Name field (pre-filled), Short Name field (pre-filled), 7-color picker row, Dark Mode toggle, Household name (read-only)
- Tapping a color circle selects it (white inset ring); previously selected circle loses the ring
- When a selected color matches another household member's color, the warning "Another member uses this color" appears below the row
- Tapping "Save Changes" sends `display_name`, `display_name_short`, and `color` to the `profiles` table update
- After a successful save, the `UserAvatar` initial and color update immediately (via `['my_profile']` invalidation)
- Toggling Dark Mode writes `'dark'` or `'light'` to AsyncStorage key `'@app_theme'`
- Tapping the X button closes the modal without saving profile changes
- The Items tab header shows undo button (with badge), redo button (with badge), and UserAvatar on the right side of the title row
- The History tab header shows undo button, redo button, and UserAvatar on the right side of the screen header
- Undo and redo buttons on Items and History tabs call the global undo/redo stack (same behavior as Shopping List)
- Undo button is opacity 0.3 and disabled when the undo stack is empty; redo button same for redo stack
