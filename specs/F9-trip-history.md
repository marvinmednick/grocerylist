## Feature: Trip History View

### Context

Users end shopping trips regularly, which archives purchased items and records a `shopping_trips` row. This data exists but is currently invisible — there is no UI to review past trips. This feature adds a Trip History tab that lists past trips and lets users drill into the items bought on each one.

This is a read-only feature. All data already exists in `shopping_trips` (trip metadata) and `list_items` (archived rows with `trip_id` set). No schema changes are required.

### New Files

- `client/api/trips.ts` — Two React Query hooks:
  - `useTripHistory()` — fetches the list of completed trips for the household, most recent first. Returns `TripSummary[]`.
  - `useTripItems(tripId: string | null)` — fetches the archived `list_items` for a given trip. Disabled when `tripId` is null. Returns `TripItem[]`.

- `client/app/(tabs)/history.tsx` — Trip History screen. Renders a `FlatList` of past trips. Tapping a row opens a `Modal` showing the items in that trip. Includes empty and loading states.

- `client/app/(tabs)/__tests__/history-test.tsx` — Component tests for the history screen (see Tests to Write).

### Database / Schema Changes

None. All required data already exists:

- `list_items`: `id`, `name`, `quantity`, `trip_id`, `store_id`, `archived_at`

### Supabase Query Shapes

**Trip list** (`useTripHistory`):
```ts
const { householdId } = useHousehold();

supabase
  .from('shopping_trips')
  .select(`
    id,
    started_at,
    ended_at,
    primary_store_id,
    store:stores!primary_store_id(name),
    list_items(id)
  `)
  .not('ended_at', 'is', null)
  .order('ended_at', { ascending: false })
```

RLS handles household scoping. The query is `enabled: !!householdId` to avoid running before the household is known. `list_items(id)` is included so item count is derived client-side as `trip.list_items.length`.

**Trip items** (`useTripItems`):
```ts
supabase
  .from('list_items')
  .select(`
    id,
    name,
    quantity,
    store_id,
    store:stores!store_id(name)
  `)
  .eq('trip_id', tripId)
  .order('name', { ascending: true })
```

Query is `enabled: !!tripId`.

**TypeScript interfaces** (define at the top of `api/trips.ts`):
```ts
export interface TripSummary {
  id: string;
  started_at: string;
  ended_at: string;
  primary_store_id: string | null;
  store: { name: string } | null;
  list_items: { id: string }[];
}

export interface TripItem {
  id: string;
  name: string;
  quantity: string;
  store_id: string | null;
  store: { name: string } | null;
}
```

### UI Behaviour

**Trip list rows** — each row displays:
- **Store name**: `trip.store?.name` or `"All Stores"` when `primary_store_id` is null
- **Date**: `trip.ended_at` formatted as a human-readable date (e.g. `"Jan 15, 2025"`) using `new Date(trip.ended_at).toLocaleDateString()`
- **Item count**: `trip.list_items.length` + `" items"` (e.g. `"12 items"`)
- A right-facing chevron icon to indicate the row is tappable

**Empty state**: When `data` is an empty array, show a centred message: `"No past trips yet"`.

**Loading state**: Show `<ActivityIndicator>` while `isLoading` is true.

**Detail modal**: Triggered by tapping a trip row.
- Title: store name (or "All Stores") + " — " + formatted date
- Close button (top right)
- `FlatList` of `TripItem` rows showing `item.name` and `item.quantity`
- Each item row also shows `item.store?.name` when it differs from the trip's primary store (useful for "All Stores" trips)
- Loading and empty states within the modal

---

### Acceptance Criteria

- A "History" tab appears in the tab bar with a history icon
- The tab lists past trips, most recent first
- Each row shows: store name (or "All Stores"), formatted end date, item count
- An empty state message appears when there are no past trips
- Tapping a trip row opens a detail modal
- The modal shows all items archived on that trip (name + quantity)
- The modal can be dismissed
- No UI appears for in-progress trips (trips with `ended_at = null` are excluded)
