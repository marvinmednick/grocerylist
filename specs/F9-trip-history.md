## Feature: Trip History View

### Context

Users end shopping trips regularly, archiving purchased items into `shopping_trips` records. This data exists but has no UI. This feature adds a History tab showing past trips with drill-down to the items on each trip.

This is a **read-only** feature for the history screen. The one mutation-side change is adding `user_id` to `useEndTrip` so trips are attributed to the user who ended them — enabling the owner display in history.

Design decisions recorded in `docs/design/F9-trip-history.md`.

### New Files

**`supabase/migrations/20250101000005_add_user_id_to_shopping_trips.sql`**
```sql
ALTER TABLE shopping_trips
  ADD COLUMN IF NOT EXISTS user_id UUID REFERENCES profiles(id);
```
Nullable — existing trip records have no owner and are treated as the current user's own trips in the UI.

**`client/api/trips.ts`** — Two React Query hooks and their TypeScript interfaces:

```typescript
export interface TripSummary {
  id: string;
  started_at: string;
  ended_at: string;
  primary_store_id: string | null;
  user_id: string | null;
  store: { name: string } | null;
  owner: { display_name_short: string | null; display_name: string } | null;
  list_items: { id: string }[];
}

export interface TripItem {
  id: string;
  name: string;
  quantity: string;
  store_id: string | null;
  store: { name: string } | null;
}
```

`useTripHistory()` — fetches completed trips for the household, most recent first:
```typescript
const { householdId } = useHousehold();

supabase
  .from('shopping_trips')
  .select(`
    id,
    started_at,
    ended_at,
    primary_store_id,
    user_id,
    store:stores!primary_store_id(name),
    owner:profiles!user_id(display_name_short, display_name),
    list_items(id)
  `)
  .not('ended_at', 'is', null)
  .order('ended_at', { ascending: false })
```
Query is `enabled: !!householdId`.

`useTripItems(tripId: string | null)` — fetches archived `list_items` for a given trip:
```typescript
supabase
  .from('list_items')
  .select(`
    id,
    name,
    quantity,
    store_id,
    store:stores!store_id(name)
  `)
  .eq('trip_id', tripId)
  .order('name', { ascending: true })
```
Query is `enabled: !!tripId`.

**`client/app/(tabs)/history.tsx`** — Trip History screen.

Key behaviours:
- On mount, retrieve the current user's ID: `supabase.auth.getUser()` in a `useEffect`, store in `currentUserId` state.
- Render a `FlatList` of `TripSummary` rows. Each row shows:
  - **Store name:** `trip.store?.name ?? 'All Stores'`
  - **Date:** `new Date(trip.ended_at).toLocaleDateString()` (e.g. `"Jan 15, 2025"`)
  - **Item count + optional owner:** if `trip.user_id === currentUserId` (or `trip.user_id` is null), show `"N items"`. If `trip.user_id` differs from `currentUserId`, show `"· [ownerName] · N items"` where `ownerName = trip.owner?.display_name_short ?? trip.owner?.display_name?.split('@')[0] ?? 'Unknown'`.
  - A right-facing chevron icon.
- Tapping a row opens the detail `Modal` and sets `selectedTrip`.
- Loading state: `<ActivityIndicator>` while `isLoading` is true (ui-guidelines §9).
- Empty state: centred `"No past trips yet"` when `data` is an empty array (ui-guidelines §10).

**Detail Modal** (React Native `<Modal>`, ui-guidelines §7):
- `animationType="slide"`, triggered by `selectedTrip !== null`.
- **Header title:**
  - Your trip: `"[storeName] — [date]"`
  - Other user's trip: `"[storeName] — [date] · [ownerName]"`
  - `storeName = selectedTrip.store?.name ?? 'All Stores'`
- Close button top-right; pressing it sets `selectedTrip` to `null`.
- `FlatList` of `TripItem` rows showing `item.name` and `item.quantity`.
- Each item row also shows `item.store?.name` in parentheses when it differs from `selectedTrip.primary_store_id`'s store (relevant for "All Stores" trips).
- `useTripItems(selectedTrip?.id ?? null)` — disabled when no trip selected.
- Loading and empty states inside the modal.

### Acceptance Criteria

- A "History" tab appears in the tab bar with a `history` icon
- The tab lists past trips, most recent first
- Each row shows: store name (or "All Stores"), formatted end date, item count
- Own trips show only item count — no owner name
- Other users' trips show owner display name before item count (`· Sarah · 8 items`)
- Falls back to email prefix if `display_name_short` is not set
- Trips with `user_id = null` are treated as own trips (no owner shown)
- Empty state message `"No past trips yet"` appears when there are no past trips
- Loading indicator appears while trip history is loading
- Tapping a trip row opens the detail modal
- Modal header for own trip: `"[Store] — [Date]"` (no owner)
- Modal header for other user's trip: `"[Store] — [Date] · [Name]"`
- The modal shows all items archived on that trip (name + quantity)
- Items from a different store than the trip's primary store show the store name in parentheses
- The modal can be dismissed via the close button
- In-progress trips (`ended_at = null`) do not appear
- `useEndTrip` sets `user_id` to the current user's ID when creating a `shopping_trips` record
