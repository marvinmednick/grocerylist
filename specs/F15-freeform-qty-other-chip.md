### Context

The qty chip row in the SmartAddItem dropdown shows predefined quantities (`default_qty` + `alternate_qtys`) as inline pills. Users who want a non-standard quantity must currently open the full edit modal. This feature adds an "Other" chip at the end of the pill row. Tapping it opens a small absolutely-positioned floating popover containing a `TextInput`. The user types a quantity and confirms with Return — the value is set as the active qty for that add, and the popover closes.

Design decisions recorded in `docs/design/F15-freeform-qty-other-chip.md`.

### Files to Modify

**`client/components/SmartAddItem.tsx`**

1. **Add popover state** — add two new state fields:
   ```typescript
   const [otherQtyPopoverItemId, setOtherQtyPopoverItemId] = useState<string | null>(null);
   const [otherQtyInput, setOtherQtyInput] = useState('');
   ```

2. **Add "Other" chip at the end of the qty pill row** — after the `.map()` that renders predefined chips (line ~225–236), append one more chip:
   - The chip label is:
     - `selection.qty` (the currently selected custom value) when `selection.qty` is **not** in the predefined list `[item.default_qty || '1', ...(item.alternate_qtys || [])]`
     - `"Other"` otherwise
   - The chip uses `styles.pillActiveBlue` / `styles.pillTextActive` (active) when the label is showing a custom value (i.e., when selection.qty is not in the predefined list)
   - The chip uses the default `styles.inlinePill` / `styles.inlinePillText` (inactive) otherwise
   - `onPress` handler: set `otherQtyPopoverItemId = item.id`, set `otherQtyInput = ''`, do **not** call `toggleSelection` yet

3. **Render the popover** — immediately after the pill row `<View>` (still inside `resultMainSection`), render conditionally when `otherQtyPopoverItemId === item.id`:
   ```tsx
   {otherQtyPopoverItemId === item.id && (
     <View style={styles.otherQtyPopover}>
       <TextInput
         style={styles.otherQtyInput}
         value={otherQtyInput}
         onChangeText={setOtherQtyInput}
         placeholder="e.g. 3 lbs"
         placeholderTextColor="#9ca3af"
         autoFocus
         returnKeyType="done"
         onSubmitEditing={() => {
           const trimmed = otherQtyInput.trim();
           if (trimmed) {
             toggleSelection(item.id, { qty: trimmed });
           }
           setOtherQtyPopoverItemId(null);
         }}
       />
     </View>
   )}
   ```

4. **Add popover styles** — add to `StyleSheet.create`:
   ```typescript
   otherQtyPopover: {
     marginTop: 6,
     backgroundColor: '#f9fafb',
     borderRadius: 8,
     borderWidth: 1,
     borderColor: '#e5e7eb',
     paddingHorizontal: 8,
     paddingVertical: 4,
   },
   otherQtyInput: {
     fontSize: 13,
     color: '#111827',
     height: 32,
   },
   ```

5. **Close popover on clearAndClose** — in the `clearAndClose` function, reset both new state fields:
   ```typescript
   setOtherQtyPopoverItemId(null);
   setOtherQtyInput('');
   ```

### Acceptance Criteria

- [ ] The qty pill row for each master item result shows an "Other" chip as the last chip
- [ ] Tapping "Other" opens a small text input popover inline (below the chip row, within the same dropdown row), with focus and keyboard already open
- [ ] Typing a quantity and pressing Return sets that value as the active qty for the item and closes the popover
- [ ] After confirming a custom qty, the "Other" chip shows the typed value with active (blue) styling; all predefined chips are shown inactive
- [ ] Selecting a predefined chip after a custom qty was entered returns the "Other" chip to its default inactive "Other" label
- [ ] Submitting an empty string from the popover does nothing (selection unchanged, popover closes)
- [ ] Tapping "Other" on a different item while a popover is already open closes the first and opens on the new item
- [ ] `clearAndClose` (called after add, cancel, etc.) resets the popover state
- [ ] Tapping the item name (quick-add) after selecting a custom qty via "Other" adds the item with that custom qty

### Tests to Write

Add to **`client/components/__tests__/SmartAddItem-test.tsx`** (do not create a new file):

```
- it('renders an "Other" chip in the qty pill row for each result item')
  → type 'Mi', wait for 'Milk' to appear, assert screen.getByText('Other') is present

- it('opens the freeform qty input when "Other" chip is tapped')
  → type 'Mi', wait for result, fireEvent.press(getByText('Other'))
  → assert a TextInput with placeholder "e.g. 3 lbs" is visible

- it('confirms freeform qty via Return and adds with that qty')
  → type 'Mi', wait for result, press 'Other'
  → fireEvent.changeText on the freeform input to '3 lbs'
  → fireEvent(input, 'submitEditing')  [or fireEvent.submitEditing]
  → press 'Milk' (item name quick-add)
  → await waitFor → assert addItem called with quantity: '3 lbs'

- it('shows the typed custom value as the active "Other" chip label after confirm')
  → type 'Mi', wait for result, press 'Other'
  → change text to '1 qt', submitEditing
  → assert screen.getByText('1 qt') is visible (chip now shows custom label)
  → assert screen.queryByText('Other') is null (label replaced)

- it('does nothing when Return is pressed on empty "Other" input')
  → type 'Mi', wait for result, press 'Other'
  → submitEditing without typing anything
  → press 'Milk'
  → await waitFor → assert addItem called with quantity: '1 gal' (original default, unchanged)

- it('resets "Other" chip label when a predefined chip is selected after custom qty')
  → type 'Mi', wait for result, press 'Other', type '1 qt', submitEditing
  → press predefined chip '1 gal'
  → assert screen.getByText('Other') is present (reverted to inactive label)
  → assert screen.queryByText('1 qt') is null
```

Note on `submitEditing`: use `fireEvent(input, 'submitEditing')` or `fireEvent.submitEditing(input)` — check existing test patterns in the file; both forms work with `@testing-library/react-native`.

The `baseItem` fixture in the test file has `alternate_qtys: []`. Use a new fixture for tests that need alternate qtys (e.g., `{ ...baseItem, alternate_qtys: ['½ gal'] }`) when needed. The existing `baseItem` is fine for the "Other" chip tests since alternate_qtys is empty.
